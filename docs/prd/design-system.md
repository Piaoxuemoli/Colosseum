> 定位声明：本文件是 Colosseum 前端重建的**唯一视觉与交互需求权威**。所有者将依据本文从零重建前端。现行 "arena 控制台" 风格（暗色、紧凑、控制室氛围）仅作为气质参考，**现有实现不构成任何约束**，重建时不得以"旧版就是这样"作为设计决策依据。本文是需求体系，不绑定任何具体实现技术、组件库或文件结构。

## 1. 设计原则

1. **暗色为主的竞技场控制台氛围** —— 整个产品像一间深夜的赛事控制室：深色底、克制的高亮、操作台式的密度，让用户感觉自己坐在赛场幕后。
2. **信息密度优先于留白** —— 这是一个观战与分析工具，不是营销页；同屏可见的信息越多，观战体验越好，留白只在分隔语义时使用。
3. **思考链是一等公民** —— AI 的推理过程是本平台区别于一切其他对战产品的核心资产，必须始终可见、可追溯、可回放，任何布局不得把思考链藏到二次点击之后。
4. **动效服务于状态理解而非装饰** —— 每一段动画都要回答"什么变了"（谁在思考、筹码增减、阶段切换）；说不清用途的动效一律删除。
5. **一屏内完成观战** —— 观战页的关键信息（赛场、当前行动、思考流）在 100dvh 视口内完整呈现，不允许整页滚动；滚动只发生在内部面板。
6. **中文优先排版** —— 界面文案以简体中文为主语言，排版按中文基线设计（标点悬挂、中英数字混排间距、避免行首标点），英文只作为兜底与术语。
7. **可长时间注视** —— 一场对局可能持续数小时，视觉设计必须降低疲劳：低饱和背景、避免大面积高亮闪烁、动效频率有节制。

## 2. 视觉语言

### 2.1 色彩体系

所有颜色以 tokens 起点给出建议值，重建时允许微调色相，但**层级语义与对比关系不可破坏**。

**背景分层（3 层深灰阶 + 1 层画布）**

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `--color-bg-canvas` | `#090B0F` | 页面最底层画布，几乎不出现在内容区 |
| `--color-bg-1` | `#0F131A` | 第一层表面：面板、卡片、导航栏底色 |
| `--color-bg-2` | `#161C26` | 第二层表面：悬浮卡片、下拉、弹层 |
| `--color-bg-3` | `#1E2634` | 第三层表面：输入框内底、hover 态、代码/日志底 |

**前景文字**

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `--color-text-1` | `#E6EBF2` | 主文字：标题、数值、关键状态 |
| `--color-text-2` | `#9AA6B8` | 次级文字：说明、标签、时间戳 |
| `--color-text-3` | `#5D6879` | 弱化文字：占位符、禁用态、历史日志 |

**语义色**（深底上直接使用，不依赖深浅两套变体时需保证对比度）

| 语义 | 建议值 | 用途 |
| --- | --- | --- |
| `--color-success` | `#3DD68C` | 成功、赢家、连接正常 |
| `--color-warning` | `#F0B34E` | 警告、超时倒计时、降级 |
| `--color-danger` | `#F2635F` | 错误、淘汰、失败、断线 |
| `--color-info` | `#4E9EFF` | 中性提示、进行中 |

**游戏氛围色（场景色）**

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `--color-scene-poker` | `#1D5C40`（桌面）/ `#8FE3B8`（点缀） | 德扑赛场：绿呢桌面与筹码高光 |
| `--color-scene-werewolf` | `#1B2A4A`（夜空）/ `#7C8CFF`（点缀） | 狼人杀赛场：黑夜蓝与月光点缀 |

场景色只用于赛场区的氛围渲染（桌面、边光、背景晕染），**不进入**通用组件的语义体系；新游戏接入时应按此模式新增一组场景 token，而不是复用语义色。

**思考链专属色**

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `--color-thought` | `#9D7BEA` | AI 推理的统一视觉标识：思考气泡边、正在思考的光效、"思考" Tab 激活态 |

思考链专属色是全站唯一的紫色系保留位，其他 UI 不得使用同族紫，以保证"看到紫 = 看到 AI 在想"的条件反射成立。

### 2.2 字体

**字体栈**

- 中文无衬线（界面主栈）：
  `system-ui, -apple-system, "Segoe UI", "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei", "Noto Sans SC", sans-serif`
- 等宽（数字、牌面、筹码、日志、代码类信息）：
  `"JetBrains Mono", "SF Mono", "Cascadia Mono", Consolas, "Noto Sans SC", monospace`
  等宽栈末尾保留中文兜底，保证中英混排日志基线一致。
- 规则：筹码数、手数、计时、牌面代号、思考链原文一律等宽；标题与正文用无衬线。

**字号阶梯（6 级）与行高**

| 级别 | Token | 尺寸 / 行高 | 用途 |
| --- | --- | --- | --- |
| 展示 | `--text-display` | 24px / 1.3 | 胜负揭晓、对局标题 |
| 标题 | `--text-title` | 18px / 1.4 | 页面与面板标题 |
| 正文 | `--text-body` | 14px / 1.6 | 默认正文、表单、日志 |
| 辅助 | `--text-secondary` | 13px / 1.5 | 说明文字、Tab 标签 |
| 微缩 | `--text-caption` | 12px / 1.5 | 时间戳、徽章、坐标轴 |
| 数值 | `--text-metric` | 16-28px / 1.2（等宽） | 筹码、底池、计时等大数字 |

正文默认不小于 13px；12px 仅用于真正的时间戳/徽章类短文本。

### 2.3 密度与栅格

- **8px 基准网格**：所有间距、尺寸取 8 的倍数（微调允许 4px 半步）。间距 token：`--space-1`(4px)、`--space-2`(8px)、`--space-3`(12px)、`--space-4`(16px)、`--space-6`(24px)、`--space-8`(32px)。
- **紧凑密度定义**：按钮/输入控件高度 28-32px；列表行高 36-40px；面板内边距 12-16px；图标与文字间距 8px。整体观感应接近专业工具而非内容网站。
- **圆角层级语义**：`--radius-sm`(4px) 基础件（标签、输入）；`--radius-md`(8px) 卡片与面板（默认）；`--radius-lg`(12px) 浮层与对话框；`--radius-full` 圆形头像/徽章。
- **边框与阴影的浮起语义**：层级越浮起，边界越明显——第 1 层表面用 1px 边框 `#232B3A`；第 2 层叠加柔和阴影 `0 4px 16px rgba(0,0,0,.35)`；第 3 层（对话框/Toast）阴影 `0 8px 32px rgba(0,0,0,.5)`。阴影只表达高度，不表达色彩情绪。

### 2.4 图标

- 约定：使用**线性（stroke）图标体系**，笔画粗细统一 1.5px，风格克制、几何，不使用填充拟物图标。
- 尺寸阶梯：14px（行内）、16px（默认）、20px（导航/工具栏）、24px（空态插画位）。
- 每个图标必须与文字标签同时可用；纯图标按钮必须提供可访问名称。

## 3. 布局系统

### 3.1 全局骨架

```
┌──┬──────────────────────────────────┐
│  │  顶部对局状态条（仅观战页）        │
│  ├──────────────────────┬───────────┤
│ 侧│                      │           │
│ 导│     主内容区          │  右侧面板  │
│ 航│                      │（仅观战页） │
│  │                      │           │
└──┴──────────────────────┴───────────┘
```

- **左侧窄导航栏**：常驻宽度 56px（仅图标）；悬停或焦点进入时展开为 240px 显示图标+文字，离开后收回。导航项：大厅、对局列表、Profile 管理、排名、设置。当前项用左侧 2px 高亮条 + 图标着色标识。
- **断点策略**：
  - 桌面 `≥1280px`：三栏（导航 + 赛场 + 右侧信息面板），观战完整形态。
  - 平板 `768-1279px`：两栏（导航 + 主内容），右侧面板降级为可从右缘唤出的抽屉，或折叠为底部 Tab 区。
  - 移动 `<768px`：单栏堆叠；观战页保留顶部状态条 + 赛场，信息面板改为赛场下方可切换 Tab；允许整页滚动（移动端豁免"一屏观战"原则）。

### 3.2 观战页布局契约（核心页面）

观战页是本产品的门面，其布局为**契约级需求**，重建后验收按此逐条检查。

- **顶部对局状态条**（高 48px，全宽）：对局名、游戏类型、当前手数/回合数、当前阶段（如"翻牌前""夜晚"）、阶段计时、SSE 连接状态徽章、（回放模式时）回放控制条吸附于此。
- **中央赛场区**（弹性主区）：游戏主视觉（座位环桌、身份布局等由各游戏自定义渲染），最小可用尺寸 640×480；赛场区内部禁止出现页面级滚动，游戏画面按可用空间自适应缩放。
- **右侧信息面板**（宽 360-480px，默认 400px，可拖拽调宽并记忆）：Tab 结构固定为：**状态 / 名册（或排名）/ 行动 / 思考 / 印象 / 走势**。思考 Tab 在有 Agent 正在思考时应显示计数角标。
- **三区比例**：状态条 48px 固定；剩余高度按 赛场 : 面板 ≈ 1.8 : 1 分配；面板不可低于 360px，赛场不可低于 640px 宽，两者冲突时优先保证面板完整并让赛场缩放。
- **100dvh 固定视口原则**：观战页 `height: 100dvh`，`overflow: hidden`；一切滚动发生在右侧面板、日志列表、思考流等内部容器；移动端除外（见 3.1）。

### 3.3 大厅 / 配置页布局契约

- **大厅（对局列表）**：卡片流布局，卡片栅格 `auto-fill, minmax(320px, 1fr)`；卡片内容：对局名、游戏类型、Agent 名单头像列、状态（进行中/已结束/等待中）、入场按钮。进行中的卡片显示"第 N 手"与在线观战感（SSE 正常徽章）。
- **Profile 配置页**：表单分区结构——"基本信息 / 模型与参数 / 人格与策略提示 / 高级"；每区独立卡片，右侧 sticky 区放校验摘要与保存按钮；长表单允许整页滚动（配置页不受一屏原则约束）。
- **对局创建向导**：左主右辅两栏——左侧分步表单（选游戏 → 选 Agent 与座位 → 参数 → 确认），右侧实时预览对局摘要。

## 5. 动效规范

- **总原则**：状态变化必须可感知，但不打断；任何动效不得阻塞交互（不占用主线程超过一帧的预算），观战页同时活跃的动画数量要有节制。
- **时长阶梯**：
  - 微交互（hover、focus、图标切换）：80-120ms；
  - 状态转换（面板展开、Tab 切换、阶段指示）：200-300ms；
  - 页面级（路由切换、对话框出入场、胜负揭晓）：350-500ms。
  - 缓动：进入用 ease-out，退出用 ease-in，移动用 ease-in-out。
- **思考气泡**：出现时淡入+上移 4px（150ms）；流式更新时新文本以低透明度 appended 后渐实，不整体跳动；完成时左侧思考色边线从动画态变为静止态；消失/折叠时高度过渡而非瞬间坍缩。
- **筹码与底池数字**：数值变化用 300-400ms 数字滚动（等宽字体保证不抖动）；符号方向（+/−）用绿/红瞬时闪光一次，不循环。
- **胜负揭晓的时刻感**：这是全场唯一允许"隆重"的时刻——获胜座位光圈扩散、展示级字号浮层、其余区域轻微压暗，总时长不超过 1.2s，且可用 Esc 跳过。
- **reduced-motion 降级**：`prefers-reduced-motion: reduce` 时，所有位移动画改为纯透明度切换或不动画；数字滚动改为直接显示终值并闪烁一次；胜负揭晓保留静态高亮。
- **时长与缓动 tokens**（与第 8 节命名规范对应）：

| Token | 值 | 用途 |
| --- | --- | --- |
| `--motion-instant` | 80ms | hover、focus、图标切换 |
| `--motion-fast` | 150ms | 气泡出现、列表项进入 |
| `--motion-normal` | 250ms | 状态转换、面板/Tab 切换 |
| `--motion-slow` | 400ms | 页面级过渡、数字滚动 |
| `--motion-ease-out` | `cubic-bezier(0.16, 1, 0.3, 1)` | 进入 |
| `--motion-ease-in` | `cubic-bezier(0.7, 0, 0.84, 0)` | 退出 |
| `--motion-ease-inout` | `cubic-bezier(0.65, 0, 0.35, 1)` | 位移与移动 |

## 6. 实时性与数据展示规则

- **SSE 增量更新节奏**：同一面板在 100-150ms 窗口内到达的多条事件必须合并为一次渲染（批量合并、与 rAF 对齐），禁止一条事件一次渲染造成抖动；新内容到达时列表不改变用户当前滚动位置（从底部跟随模式除外）。
- **跟随与锚定**：日志/思考流默认"跟随最新"，用户向上滚动即切换为"锚定历史"并显示"回到最新"浮标；用户主动滚回底部才恢复跟随。
- **长对局性能约定**：行动日志与思考流超过约 200 条时必须虚拟化；走势图数据点超过可视像素数 2 倍时降采样（保留极值点，不只均匀抽样）；长时间观战页面内存不得持续增长（事件缓冲有上限，更早内容按需分页加载）。
- **断线重连视觉状态**：连接状态徽章三态——正常（success）/ 降级重连中（warning + 转圈）/ 失联（danger）；重连成功后先静默补齐增量，若缺口过大则显示"已追至第 N 手"的摘要条，不整页刷新。

## 7. 无障碍与品质基线

- **对比度**：正文文字对背景 ≥ 4.5:1（WCAG AA）；大字号（≥18px 粗体）与 UI 边界 ≥ 3:1；语义色在深底上的文字用法必须逐一验证，不达标时提供加亮变体。
- **键盘可达**：全部操作可用键盘完成；焦点顺序符合视觉顺序；自定义控件（Tab、座位卡、回放条）实现完整键盘语义。
- **全局快捷键约定**：`?` 打开快捷键帮助；`g` 打开导航跳转（再按字母跳页面）；`n` 新建对局；观战页 `1-6` 切换右侧面板 Tab；`空格` 回放播放/暂停；`Esc` 关闭浮层/跳过揭晓动画。快捷键不得在输入框聚焦时触发。
- **focus 可见**：所有可聚焦元素有 ≥2px 的焦点环（info 色或思考色），与背景对比 ≥ 3:1；禁止 `outline: none` 而无替代。
- **屏幕阅读器最低要求**：对局状态条、当前行动者变更、胜负结果通过 `aria-live`（关键结果 assertive，其余 polite）广播；思考流不逐条广播，提供"停止播报"开关；所有图标按钮有 `aria-label`；颜色不是唯一信息载体（淘汰/赢家等状态需有图标或文字并行标识）。

## 8. 交付约定

- **tokens 组织**：全部设计常量以 CSS 自定义属性交付，收敛在单一 tokens 层，组件只引用 token，不写裸值（一次性装饰值除外）。
- **命名规范**：`--{类别}-{名称}-{变体}`，类别前缀固定：`--color-*`（bg/text/semantic/scene/thought）、`--space-*`、`--text-*`、`--radius-*`、`--shadow-*`、`--motion-*`（时长/缓动）。示例：`--color-bg-1`、`--space-2`、`--motion-fast`。中划线分隔，全小写。
- **组件验收流程**：每个组件合入前对照本文档逐条检查——(1) 用到的颜色/字号/间距是否全部来自 token；(2) 关键状态清单是否全部实现（第 4 节表格）；(3) 键盘与焦点是否可达；(4) 动效时长是否落在阶梯内、reduced-motion 是否降级；(5) 中文排版（字号下限、混排）是否合规。任何一条不满足须记录豁免理由。
- **文档同步**：tokens 值调整、组件状态增减，必须回写本文档并升版本号，保持本文与实现一致。
