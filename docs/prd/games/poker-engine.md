## 1. 范围与定位

### 1.1 引擎是什么

德州扑克引擎是一个**纯逻辑规则机**：接收对局配置与动作输入，产出状态推进与事件输出。完整职责链：

**配置校验 → 洗牌发牌 → 动作合法性校验 → 下注街推进 → 摊牌结算 → 多手牌锦标赛循环（含淘汰、盲注升级）→ 终局结算**。

引擎不做任何 I/O，不感知时间，不调用外部服务，不隐藏私有信息（信息隔离通过"按受众投影"的输出能力实现，见 PFR-4xx）。

### 1.2 职责边界

| 归属 | 职责 |
|---|---|
| 引擎（本文件） | 规则正确性、状态与事件契约、锦标赛循环、按受众的信息投影、供决策的机械派生量 |
| 平台编排层 | 行动时限与超时处置、LLM 调用与输出解析容错、prompt 构造、观战推送与持久化、并发调度 |
| Agent / 分析侧 | 策略量计算（equity、ICM 等，见 PFR-502 划界）、人设与决策本身 |

### 1.3 术语

- **手（hand）**：一手牌，从洗牌发牌到结算完毕的完整周期；**街（street）**：手内的下注轮（preflop / flop / turn / river）。
- **锦标赛语义**：淘汰制，筹码是分数，打至单人存活（见 PFR-101）。

## 2. 对局形态与配置需求（PFR-1xx）

**PFR-101 锦标赛对局形态（P0）**
描述：对局采用锦标赛（淘汰制）语义：所有玩家以相同起始筹码入局，持续逐手进行；筹码归零者当场出局并确定名次；最后一名存活者夺冠，终局排名按出局逆序推定。
验收标准：
- Given 任一玩家筹码归零，When 该手结算完成，Then 该玩家被标记出局，不再参与后续手牌，且出局名次当场确定并留痕。
- Given 存活玩家仅剩 1 人，When 该手结算完成，Then 对局进入终局，产出完整排名（存活者第一，其余按出局逆序）。
- Given 终局排名，When 按事件流逐手回推出局顺序，Then 排名可被过程数据验证，无凭空名次（对齐上游 FR-4.6-01）。

**PFR-102 对局配置项（P0）**
描述：创建对局时须可配置下表各项；引擎对配置做合法性校验，非法配置在开局前拒绝。
验收标准：

| 配置项 | 约束 | 默认 |
|---|---|---|
| 参赛人数 | 2–9；2 人时启用 heads-up 特殊规则（PFR-204） | 无默认，必填 |
| 起始筹码 | 正整数；全员相同 | 无默认，必填 |
| 初始盲注（SB/BB） | 正整数且 SB < BB | 无默认，必填 |
| 盲注升级计划 | 可禁用（= 固定盲注）；启用时须给出升级间隔（每 N 手）与各级盲注值序列（PFR-112） | 禁用 |
| 按钮位（庄家位）初始随机化 | 首手按钮位由受控随机决定并进入事件流（PFR-404）；其后每手移至下一存活座位（简化移位口径：不实现完整死按钮规则，须在规则口径中显式声明） | — |
| 下注制 | v1 仅支持 no-limit（无限注，PFR-104） | no-limit |

- Given 人数为 1 或 10、SB ≥ BB、升级间隔非正整数等任一非法组合，When 提交配置，Then 引擎拒绝并给出结构化的具体原因，不进入发牌。

**PFR-103 行动时限不属引擎（P0，边界约定）**
描述：行动时限、超时惩罚、重试节奏均属平台编排层。引擎不内置计时器、不感知时间；平台层对超时玩家的处置以"注入一个动作"的方式进入引擎（典型为 fold），注入动作与普通动作走同一合法性校验。
验收标准：
- Given 引擎在任何状态，Then 其全部输入仅为（配置、动作、受控结束指令），不存在时间类输入。
- Given 平台层注入某玩家的超时 fold，When 引擎校验该动作，Then 与玩家主动 fold 完全同构（同校验、同事件形态，可由平台层附加标记区分来源）。

**PFR-104 下注制：no-limit 为默认且 v1 唯一（P0）**
描述：v1 完整实现 no-limit（无限注德州扑克，NLHE）：任意时刻可下注至全部筹码；最小下注与最小加注规则见 PFR-206。pot-limit 与 fixed-limit 不在 v1 范围，是否进入 v2 见 OD-P1。
验收标准：
- Given 任意可下注状态与任意不超过行动者筹码的合法金额，When 行动者声明该金额的下注/加注/全下，Then 引擎按 no-limit 规则校验并接受（符合最小额约束时）。
- Given v1 版本，Then 不存在 pot-limit / fixed-limit 的配置入口。

**PFR-105 受控结束指令（P0）**
描述：引擎接受平台层发起的两种受控结束指令，以支撑上游 FR-4.3-03：a) 当前手结束后终止——完成当前手结算后进入终局；b) 立即终止——按当前筹码与存活状态结算排名，并在终局事件中标注人为终止及终止时点。
验收标准：
- Given 指令 a 下发于某手进行中，When 该手结算完成，Then 不再开始新手，直接进入终局，不存在手牌中途截断的中间态。
- Given 指令 b 下发，When 终局事件产出，Then 含"人为终止"标注与终止时点，此前全部事件完整保留。

## 3. 规则正确性需求（PFR-2xx）

规则口径总则：线上惯例与 Poker TDA 规则冲突时，以 TDA 为准；本节内联声明所有与变体有关的口径选择。

**PFR-201 牌型评估：best 5 of 7 与 kicker（P0）**
描述：摊牌比牌从 7 张可用牌（2 底牌 + 5 公共牌）中任选最优 5 张构成牌型；底牌可 0/1/2 张参与。牌型从大到小：皇家同花顺（同花顺特例）、同花顺、四条、葫芦、同花、顺子、三条、两对、一对、高牌。同级牌型按各自比较键逐位比较，全部相等才为平局。花色永不参与大小比较。A-2-3-4-5（轮子）为顺子/同花顺中以 5 为高的最低档。
验收标准：
- Given 公共牌为 A-A-K-Q-J 且所有存活者底牌均无法改进牌型，Then 所有人"打板"成一对手 A、kicker K-Q-J，判定为平局。
- Given 玩家甲 顺子 A-2-3-4-5 与玩家乙 顺子 2-3-4-5-6，Then 乙胜（轮子以 5 为高，是最小顺子）。
- Given 两家牌型与五张比较键完全相同但花色不同，Then 平局（花色不破平）。
- Given 同一 7 张牌输入，Then 评估结果唯一且与"从 21 种五张组合中取最强"的规范语义一致（覆盖全部牌型类别与 kicker 维度的系统化用例，见 PFR-602）。

**PFR-202 平局分池与奇数筹码归属（P0）**
描述：单一池内平局赢家 n 人均分；除不尽的余数逐枚分配。奇数筹码归属采用 TDA 板牌类规则：自按钮位左侧第一个有分池资格的座位起，顺时针逐枚分配。每个池（含边池）独立执行分割与奇数筹码归属。
验收标准：
- Given 某池 101 筹码由 3 人平分，Then 每人 33，余 2 枚自按钮左侧第一个有资格座位起顺时针各得 1 枚。
- Given 任意分池场景，Then 奇数筹码归属结果唯一确定，不依赖任何排序实现的偶然顺序。
- Given 边池出现平局，Then 边池独立按本条规则分割，主池结果不受影响。

**PFR-203 街结构与发牌（P0）**
描述：每手按 preflop → flop（3 张公共牌）→ turn（1 张）→ river（1 张）推进。烧牌为线上形式性行为，允许省略；若保留，须以占位事实进入事件流且不影响任何判定。弃牌至仅剩一人时，该手立即结束：剩余者直接赢得池，不摊牌、不发剩余公共牌。
验收标准：
- Given 一手打满四条街，Then 公共牌依次为 3/1/1 张，街切换时点与事件顺序一一对应。
- Given 弃牌至仅剩 1 人，Then 不再发出任何公共牌，无摊牌事件，池立即归剩余者。
- Given 采用烧牌占位，Then 占位事件不改变任何比牌与发牌结果（对拍无差异）。

**PFR-204 行动顺序（P0）**
描述：
- 3 人及以上：preflop 自 BB 左侧第一位（UTG）起顺时针行动，BB 拥有 option（无人加注时可 check 或 raise）；postflop 自按钮左侧第一位仍在手玩家起顺时针，按钮位最后行动。
- Heads-up（2 人）：按钮位即 SB；preflop 按钮（SB）先行动，postflop BB 先行动。
- 座位状态变化（弃牌、出局、全下）后，后续行动顺序按存活关系顺延，规则不变。
验收标准：
- Given 3 人局无人弃牌的 flop，Then 行动顺序为 SB → BB → 按钮。
- Given heads-up 的 preflop，Then 按钮先行动；given heads-up 的 flop，Then BB 先行动。
- Given 按钮位或其左侧玩家已弃牌，Then 该手后续街的第一行动者正确顺延至下一个存活在手玩家。

**PFR-205 动作合法性与街结束条件（P0）**
描述：动作集为 fold / check / call / bet / raise / all-in。一条街结束当且仅当：所有未弃牌玩家对当前最高下注额均已行动且金额跟平（BB 的 option 计为一次行动）。跟注额超过行动者剩余筹码时，以其全部筹码视为 all-in 跟注，仍视为跟平。
验收标准：
- Given preflop 无人加注且行动轮到 BB，Then BB 可 check（option）或 raise，不得被强制 call。
- Given 行动者剩余筹码 50、需跟注 80，When 其声明 call，Then 视为 50 全下跟注，且后续按边池规则（PFR-208）处理。
- Given 一条街结束条件未满足（尚有玩家未对当前最高额行动），Then 引擎不得推进到下一街。

**PFR-206 最小加注与不足额全下（P0）**
描述：
- 最小加注增量 = 本街最近一次 bet/raise 的增量（不是"加到额"）；街内首个下注的最小额 = 1 BB；preflop 的盲注视为首个下注（BB 额为基准增量）。
- **不足额全下不重开行动（full-bet 口径，本 PRD 显式采用）**：全下金额不足以构成一次完整加注时，不构成有效加注、不重开已行动玩家的行动权——已行动者只能跟平差额或弃牌。"达到半个增量即重开"的 half-bet 变体不采用，口径在此声明。
验收标准：
- Given 盲注 1/2，UTG 加注到 8（增量 6），Then 下一位的最小 re-raise 为再加 6 至 14。
- Given 盲注 1/2，无人加注时首个下注，Then 最小 bet = 2（1 BB）。
- Given 加注到 8（增量 6）后，某已行动玩家之外的全下仅加到 11（增量 3，不足 6），Then 先前已行动的玩家重新轮到时只能 call 11 或 fold，不得 raise。
- Given 任一街，Then 引擎正确追踪"最近一次加注增量"与"各玩家是否已被完整加注重开行动"，跨街重置。

**PFR-207 金额边界与非法动作处理（P0）**
描述：动作金额必须落在引擎给出的合法区间内（区间边界即 PFR-501 的合法动作集）。引擎对非法动作一律**结构化拒绝**，绝不静默修正、绝不静默夹取。两类例外构成合法的"不足额"：a) 全下（金额 = 行动者全部剩余筹码）；b) 短盲注（PFR-211）。声明金额超过剩余筹码的下注/加注非法（应表达为 all-in）。
验收标准：
- Given 行动者声明 bet 500 而剩余筹码 300，When 提交，Then 被拒绝并返回结构化原因（金额越界），不自动折算为 300 全下。
- Given 行动者声明 raise 至低于最小加注额且非全下，When 提交，Then 被拒绝并附具体合法区间。
- Given 非行动者提交动作、终局后提交动作、或对已结束的街提交动作，Then 均被拒绝且原因可区分。

**PFR-208 边池（P0）**
描述：按各玩家**整手牌累计贡献额**分层构建主池与边池：贡献层级升序切分，内层为主池，外层依次为边池。每个池的参赛资格独立判定——玩家仅与累计贡献不超过自身贡献上限的对手竞争；全下玩家可赢主池及自己有资格的池，永远不能赢超出其贡献的更外层边池。弃牌者的贡献保留在相应池中，但弃牌者无任何池的资格。某层仅剩单一有资格者时该池直接归其。各池独立比牌、独立分割、独立处理奇数筹码。
验收标准：
- Given 甲全下 100、乙全下 300、丙跟注 300：Then 主池 300（甲/乙/丙三人资格）、边池 400（乙/丙两人资格）；甲即使牌最强也只赢主池。
- Given 上述场景中甲、乙、丙全部摊牌且甲最强，Then 甲得 300，边池 400 在乙/丙中按牌判定。
- Given 某层贡献仅来自弃牌者（无有资格者），Then 该层金额并入规则明确的相邻池，不产生悬空筹码。
- Given 一手结算完成，Then 全部池金额之和恒等于该手全体玩家贡献之和（筹码守恒）。

**PFR-209 摊牌顺序与亮牌（P0）**
描述：river 有下注时，最后的进攻者（最后一次 bet/raise 者）先亮牌，其后按顺序依次亮牌；无人下注时自按钮左侧第一位仍在手玩家起依次亮牌。要赢池必须亮出全部底牌；已弃牌者的底牌不因摊牌而揭示。弃牌致胜（PFR-203）不发生摊牌。全下 run-out 场景下所有在池玩家须亮牌。亮牌以带顺序的揭示事件进入事件流；muck（不亮牌认输该池）权利是否保留见 OD-P3。
验收标准：
- Given river 有 bet 且被跟注，Then 揭示事件序列以最后进攻者开头，顺序正确留痕。
- Given river 无任何下注，Then 揭示自按钮左一存活在手玩家开始。
- Given 全下 run-out 结算，Then 全部在池玩家的底牌均经揭示事件转为公共信息。
- Given 任意手结束，Then 每个池的赢家集合及其最终五张牌可从事件流完整复原。

**PFR-210 全员全下自动 run-out（P0）**
描述：当下注阶段结束后，在手玩家中至多一人仍保有可改变下注额的行动能力（其余全部 all-in，或仅剩一人在手但存在待结算的池）时，引擎**自动连续发完剩余公共牌（逐街发、逐街产生事件）并完成摊牌结算**。该推进由引擎内部驱动，不依赖任何外部动作输入，不得中断，不得因此提前终结整场比赛。
验收标准：
- Given 3 人在 flop 前全部 all-in，Then 引擎自动依次发出 flop / turn / river（各成事件），随后摊牌、分池、结算，随后正常开始下一手，整场比赛继续。
- Given run-out 全过程，Then 事件流中无任何"等待动作"状态，比赛推进不被阻断。
- Given 仅 2 人在手且一方 all-in 被跟注，Then 同样触发自动 run-out。

**PFR-211 盲注（P0）**
描述：SB/BB 为活注：BB 在 preflop 无人加注时保有 option。短盲注（玩家筹码不足以支付盲注）时按剩余筹码全下（引擎代为提交），该玩家保留对应位置的权利（如 BB 短注后仍只需跟平差额）。
验收标准：
- Given SB 玩家筹码 1 而应缴 2，When 手牌开始，Then SB 提交 1 并处于全下状态，事件留痕。
- Given BB 玩家短盲全下且无人加注，Then 无需其再行动，直接进入 run-out 或摊牌结算。
- Given 盲注已提交，Then 盲注金额计入该玩家本手累计贡献（参与边池分层）。

**PFR-212 盲注升级（P0，配置启用时）**
描述：升级计划启用时，按配置的间隔（每 N 手）与盲注值序列驱动：升级时点为新一手开始前，当手起全程使用新盲注级。升级必须以事件留痕。升级计划禁用时全程固定盲注（与 PFR-102 默认一致）。
验收标准：
- Given 配置每 10 手升级且第 1–10 手盲注 1/2、第 11 手起 2/4，When 第 11 手开始，Then 该手按 2/4 提交盲注，且升级事件在事件流中位于该手开始事件之前。
- Given 升级时某存活玩家筹码低于新 BB，Then 该玩家按短盲规则（PFR-211）处理，手牌正常进行。

## 4. 状态与推进需求（PFR-3xx）

**PFR-301 不可变状态与纯函数推进（P0）**
描述：状态一经产出不可变；推进以"（状态，输入）→（新状态，事件序列）"的纯函数语义进行：相同输入必产出完全相同的新状态与事件序列；推进不修改原状态、不产生输入之外的副作用。
验收标准：
- Given 同一状态与同一合法输入被重复推进，Then 两次输出的新状态与事件序列完全一致。
- Given 任一推进发生前后，Then 原状态对象的内容不变。
- Given 引擎全部能力，Then 不存在绕过该语义的隐藏可变全局（时区、随机数、计数器等均不得隐式影响结果——随机性只能经 PFR-404 的受控通道进入）。

**PFR-302 当前行动者不变式（P0）**
描述：引擎须满足不变式：任意时刻，手牌要么处于"存在唯一确定的当前行动者且其合法动作集非空"状态，要么处于引擎将继续自动推进的状态（发牌、run-out、结算、手牌切换、终局），二者必居其一。不存在"无人可行动而对局停滞、手牌未完成"的第四态。街结束、手牌结束的判定条件（PFR-205/203）是推进的唯一依据。
验收标准：
- Given 任意可序列化状态，Then 可判定其归属上述两类状态之一，且该判定可由规则从状态字段推导（不依赖外部信息）。
- Given 任何动作序列（含大量连续全下与弃牌），When 逐步推进，Then 不出现停滞态：每次推进后要么给出下一行动者，要么自动产出发牌/结算/终局事件直至需要新的行动输入。

**PFR-303 超时与无响应的边界（P0）**
描述：引擎不感知时间、不执行超时。玩家无响应的处置（超时 fold、平台兜底策略）由平台层决策并以动作注入（与 PFR-103 同一机制）。引擎保证：任何被注入的动作经过与玩家动作完全一致的校验，且注入本身不破坏 PFR-302 不变式。
验收标准：
- Given 平台层对长时间无响应者注入 fold，Then 引擎按普通 fold 校验、推进并产出同构事件（来源标记由平台层附加）。
- Given 任意注入时点，Then 不出现引擎停滞或状态错乱（与 PFR-302 联合验证）。

## 5. 事件契约需求（PFR-4xx）

**PFR-401 事件即事实日志（P0）**
描述：对局的全部真相以事件流承载：每个事件是一条不可变的增量事实，携带对局内单调递增的序号（seq）；事件**不得内嵌全量状态快照**（快照的定位见 PFR-405）。事件顺序与发生顺序严格一致。
验收标准：
- Given 任意事件流，Then seq 严格单调递增且无空洞。
- Given 任意事件，Then 其内容为增量事实（本事件发生的变化），不包含可由前序事件推导的全量状态。
- Given 两段相同起点与相同动作序列的对局，Then 产出的事件流逐事件一致。

**PFR-402 最小事件集（P0）**
描述：事件集至少覆盖下表；每个事件标注受众等级——**公共**（全员与观众实时可见）、**仅本人**（仅该玩家私有）、**延迟公开**（终局或该手结算后转为公共，用于审计与回放）。

| 事件（语义名） | 时机 | 受众 |
|---|---|---|
| 对局配置确立（含全部规则参数） | 创建时 | 公共 |
| 手牌开始（手号、按钮位、盲注级） | 每手 | 公共 |
| 洗牌随机性确立（种子或等价随机性材料） | 每手洗牌 | 延迟公开 |
| 底牌发放（逐玩家） | 每手 | 仅本人 |
| 盲注提交（含短盲全下） | 每手 | 公共 |
| 烧牌占位（若启用） | 各街发牌前 | 公共 |
| 公共牌发放（flop/turn/river） | 各街 | 公共 |
| 玩家动作（动作类型与金额） | 每动作 | 公共 |
| 自动推进（run-out 逐街发牌标记） | 全下后 | 公共 |
| 亮牌揭示（带顺序） | 摊牌 | 公共（揭示时刻起） |
| 分池与授予（各池赢家、平分、奇数筹码归属） | 结算 | 公共 |
| 手牌结束摘要（各玩家盈亏、出局标记） | 每手结算 | 公共 |
| 盲注升级 | 升级时点 | 公共 |
| 玩家淘汰（名次） | 筹码归零 | 公共 |
| 终局（最终排名、结束方式：自然 / 受控） | 终局 | 公共 |

验收标准：
- Given 一手完整打满至摊牌的对局，Then 上述适用事件全部出现且时序正确。
- Given 任意受众（某选手、观众、审计），Then 其消费到的事件视图均按受众等级过滤后的投影，且互不越权。

**PFR-403 底牌信息隔离（P0）**
描述：底牌事件的受众为"仅本人"：在其他选手、观众的一切实时消费视图中，终局（该手摊牌/结算）之前不得出现未揭示的底牌内容——**观众同样是延迟揭示**，仅经 PFR-209 的揭示事件或该手结算后才转为公共。上游 PRD 的"上帝视角观战"属呈现层需求，不得以引擎事件契约默认输出未揭示底牌的方式实现；引擎按受众投影的能力是呈现层实现该需求时的唯一合规信息来源。
验收标准：
- Given 观众视角订阅一场进行中对局的事件投影，When 某手尚未摊牌，Then 投影中不含任何未揭示底牌内容。
- Given 某选手视角，Then 其可见的他人底牌范围与观众一致（终局前为零）。
- Given 某手结算完成，Then 已揭示的底牌（揭示事件覆盖者、终局公开者）在后续投影中保持可见。
- Given 对引擎输出做信息泄露审计，Then 除"仅本人"受众通道外，检索不到未揭示底牌的任何明文或可推导等价物。

**PFR-404 随机性入事件流（P0）**
描述：所有影响结果的随机性（每手洗牌、首手按钮位）必须以受控、可复现的方式产生，并将随机性材料（种子或等价物）以事件形式进入事件流（受众：延迟公开）。每手的随机性相互独立派生，支持单手单独复现。引擎不得存在事件流之外的第二随机源。
验收标准：
- Given 同一对局配置与同一初始随机性材料，When 完整重放全部动作，Then 每手牌序、按钮位、全部事件与终局完全一致。
- Given 仅重放某一手（该手随机性材料 + 该手动作序列），Then 可独立复现该手全部结果。
- Given 对引擎做确定性审计，Then 找不到未被事件流覆盖的随机性来源。

**PFR-405 事件流重建任意状态（P0）**
描述：从"对局配置事件 + 有序事件流"出发，可重建任意 seq 时点的完整状态（含已发牌序、各池、各玩家状态）。快照是重建的加速优化，**不是真相来源**：任何快照必须可由事件流推导验证；回放与审计以事件流为准。
验收标准：
- Given 任一事件流与任一 seq，When 执行重建，Then 得到的状态与实时推进至该 seq 的状态完全一致。
- Given 任意快照，When 用事件流重建同一 seq 的状态对比，Then 二者一致，否则以事件流为准并判定快照失效。

## 6. Agent 适配需求（PFR-5xx）

**PFR-501 决策上下文派生量（P0）**
描述：遵循"机械量引擎算、策略量 agent 算"。引擎（或其只读查询能力）必须向决策方提供下列全部派生量，且与引擎内部校验使用同一套规则口径：
- 当前街每个合法动作及其金额上下界（min / max，含 bet 与 raise 的"加到额"口径）；
- 最小合法加注额与当前加注增量（PFR-206）；
- pot odds 口径数据：当前需跟注额、跟注后总池（跟注额 ÷（当前池 + 跟注额）可直接得出）；
- 有效筹码（行动者与各对手间的最大可对撞额）；
- 位置标签（BTN/SB/BB/UTG/CO 等相对按钮的语义标签，逐玩家给出）。
验收标准：
- Given 任意需要行动的状态与行动者，Then 查询返回的合法动作集与引擎校验接受的集合完全一致（查询说合法的必须被接受，说不合法的必须被拒绝——与 PFR-207 联合验证）。
- Given 派生量数值，When 用规则手工复核，Then 与引擎输出一致（以表驱动用例覆盖 min-raise、有效筹码、pot odds 的边界）。
- Given 只读查询被任意次调用，Then 不改变状态、不产生事件（查询与推进严格分离）。

**PFR-502 引擎不提供策略量（P0，划界）**
描述：equity / 胜率、ICM、bubble pressure 等策略层派生量**不由引擎提供**。引擎仅保证提供计算它们所需的原始事实：全员筹码快照、名次与淘汰序列、（若配置）名次奖池分配表。是否将策略量注入 agent 上下文属平台层决策（OD-P6）。
验收标准：
- Given 引擎对外能力清单，Then 不存在 equity / ICM 类输出；筹码与名次事实完整可得。
- Given 上层自行基于引擎事实计算策略量，Then 所需输入无缺口。

**PFR-503 非法动作的结构化拒绝（P0）**
描述：非法输入（动作或金额）的拒绝响应必须机器可读、原因可编程区分，至少覆盖：非行动者 / 当前状态不接受该动作类型 / 金额越界（低于最小额或高于筹码）/ 低于最小加注且非全下 / 手牌或对局已结束。该结构化原因是平台三层容错链（解析→规范化→降级）的输入；引擎侧绝不静默修正（与 PFR-207 一致）。
验收标准：
- Given 各类非法输入的代表性用例，Then 每类返回独立可区分的原因编码或等价结构，且附合法区间信息。
- Given 非法输入，Then 引擎状态与事件流零变化（拒绝无副作用）。

## 7. 非功能需求（PFR-6xx）

**PFR-601 确定性（P0）**：同一配置 + 同一初始随机性 + 同一动作序列 ⇒ 完全一致的事件流、状态与终局；随机性仅经 PFR-404 通道进入。验收：任意对局重放两次做逐事件比对，零差异；跨平台重放结果一致（不依赖浮点顺序敏感运算的偶然性）。

**PFR-602 可测试性（P0）**：全部规则条目可用表驱动用例表达与执行（输入：状态 + 动作/配置；期望：事件 / 状态断言 / 拒绝原因）；牌型比较器须通过覆盖全部牌型类别 × kicker 维度 × 平局情形的系统化用例集；第 8 节验收用例 100% 可自动化执行。验收：规则回归以用例表为唯一口径，新增规则缺陷必须先沉淀为失败用例再修复。

**PFR-603 性能（P1）**：常规硬件下，单个动作推进的引擎内计算 ≤ 5ms；一手完整结算（含摊牌、多层分池、run-out）≤ 50ms；以上均不含平台层的 LLM 与网络耗时。验收：在人数上限（9 人）、多池嵌套的最坏构造用例下满足上限。

**PFR-604 可扩展性（P1）**：规则维度（下注制、底牌张数、公共牌张数、ante 等）以可参数化的能力组织，事件契约与状态模型不得被单一变体硬编码封死——Omaha / 短牌等新变体不在 v1 范围，但接入不应推翻本契约（扩展立项决策见 OD-P8）。验收：以"新增 pot-limit 只新增参数与规则分支、不改事件语义"为设计评审判据。

## 9. 验收标准：v1 规则验收用例清单

以下用例是 v1 规则验收的最小集合，全部须可自动化执行（PFR-602）；每条须以"事件流断言 + 状态断言"双口径验证。

| 编号 | 场景 | 引用 | 期望要点 |
|---|---|---|---|
| AC-01 | river 前全员 all-in 的 run-out | PFR-210 | flop 前 3 人全下：自动逐街发完公共牌（每街独立事件）→ 全员亮牌 → 分池结算 → 比赛正常进入下一手，不中断、不提前终局、奖池全额发放 |
| AC-02 | min-raise 与不足额全下 | PFR-206 | 盲注 1/2：加注到 8 后最小 re-raise 为 14；增量 3 的全下（至 11）不重开已行动者行动权，其只能 call 11 / fold |
| AC-03 | 嵌套边池 | PFR-208 | 100 / 300 / 500 三级贡献：主池与两级边池各自独立判胜；短码玩家只赢有资格的池；全池总和 = 总贡献（守恒） |
| AC-04 | Heads-up 特殊顺序 | PFR-204 | 按钮 = SB；preflop 按钮先行动；postflop BB 先行动；多手间按钮正确轮转 |
| AC-05 | 平局与奇数筹码 | PFR-202 | 3 人平分含奇数余量的池：均分正确，余数自按钮左侧第一个有资格座位起顺时针逐枚分配，结果唯一 |
| AC-06 | 短盲全下 | PFR-211 | SB 筹码不足：代提交全下并留痕，位置权利保留；BB 短盲时无加注场景不产生多余等待 |
| AC-07 | 盲注升级 | PFR-212 | 每 N 手升级：新手开始前生效、事件先于手牌开始事件、短码玩家按短盲规则继续 |
| AC-08 | 淘汰与单人终局 | PFR-101、PFR-105 | 筹码归零即出局并定名次；单人存活时自然终局；受控结束（当前手后终止 / 立即终止）均产出完整排名与标注 |

| AC-12 | 牌型比较系统用例 | PFR-201 | 覆盖 10 类牌型、kicker 逐位比较、打板平局、轮子（A-5 为低）、花色不破平 |
