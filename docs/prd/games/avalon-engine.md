## 0. 范围与定位

### 0.1 引擎是什么

阿瓦隆引擎是一个**纯逻辑规则机**，职责链路为：

**配置（板子）→ 初始局生成（发牌 + 夜间情报）→ 合法动作校验 → 状态推进 → 事件流输出 → 终局裁决（含刺杀环节）**

- 输入：板子配置 + 外部提交的动作序列（发言 / 提名 / 表决 / 任务抉择 / 刺杀指认）。
- 输出：追加式受众标记事件流、按受众口径的决策上下文、终局结果（胜方阵营 + 过程依据 + 身份揭示）。
- 引擎是可独立验证的规则权威：同一配置 + 同一动作序列 + 同一显式随机种子，永远得到同一结果（AVR-N1）。

### 0.2 引擎不是什么

| # | 不含 | 归属 |
|---|---|---|
| 1 | AI 策略、发言文本生成 | Agent 侧；引擎只提供决策上下文与动作空间（发言内容作为动作载荷透传，引擎不判内容） |
| 2 | UI / 观战呈现 | `docs/prd/games/avalon-frontend.md` |
| 3 | 主持人旁白 | 产品 PRD FR-4.7；引擎只提供事实事件 |
| 4 | LLM 调用、超时重试 | 平台层；引擎只定义无响应时的默认动作契约（AVR-304） |
| 5 | 对局管理 | 产品 PRD FR-4.3 |

### 0.3 与产品需求的衔接

- 引擎事件流是观战（FR-4.4）、回放（FR-4.6）、异常清单（FR-4.8）的数据地基。
- 全量化是「品类即插件」（FR-4.5-03 / NFR-08）的正式验收形态：全量规则接入不得引入平台核心分支改动。
- 分期：**v1 全量**（本文全部 v1 条目：5/6 人板全量规则 + 7–10 人板配置能力）→ **v2**（领袖道具、湖中女神等扩展，见第 8 节非目标）。

## 1. 核心设计需求（AVR-1xx）

优先级标注：v1 / v2；带 P0 者为 v1 不可裁剪项。

### AVR-101 配置驱动（v1，P0）

描述：任何对局由「板子配置」完整定义；引擎不硬编码任何板子、人数、角色与规则口径。

验收标准：
- Given 任意合法板子配置，When 用于开局，Then 引擎按配置生成初始局，不依赖内置特定人数或角色假设。
- Given 非法配置（人数与角色数不符 / 阵营配比错 / 未知角色 / 参数越域），When 提交，Then 开局前被拒绝并返回结构化原因。
- Given 两局使用同一配置与同一动作序列（+ 同一种子），Then 结果完全一致。

板子配置最小字段需求表：

| # | 参数（语义名） | 取值域 | 约束 | 分期 |
|---|---|---|---|---|
| 1 | 板子标识 | 字符串 | 预设引用或显式配置 | v1 |
| 2 | 玩家数 | 5–10 | 与角色总数一致 | v1 |
| 3 | 角色构成 | {角色: 数量} | 阵营配比符合第 6 节板子表；好人必含梅林；坏人必含恰好 1 名刺杀权持有者（见 AVR-106） | v1 |
| 4 | 任务轮数 | 5（固定） | v1 不开放配置 | v1 |
| 5 | 每轮任务人数表 | 按板子表给出 | 长度 = 任务轮数 | v1 |
| 6 | 双失败轮 | 轮次集合（如 {4}）或空 | 仅允许数值 > 1 的轮次 | v1 |
| 7 | 胜利所需任务成功数 / 失败数 | 3 / 3（固定） | v1 不开放配置 | v1 |
| 8 | 连续拒绝上限 | 5（固定，标准口径） | 达成即坏人胜利（AVR-403） | v1 |
| 9 | 讨论阶段开关 | 开 / 关 | 默认开（AVR-301） | v1 |

### AVR-102 阶段机驱动（v1，P0）

描述：对局是显式阶段机的循环：**讨论 → 提名 → 队伍表决 →（通过）任务执行 →（结算）→ 下一轮讨论**；表决不通过则回到提名（同轮重新提案）；好人拿满 3 个任务成功后进入**刺杀环节**。

验收标准：
- Given 任意进行中对局，Then 有且仅有一个当前阶段，且当前待行动者唯一（或为空 = 已终局）。
- Given 阶段切换，Then 发出公共阶段进入事件。

### AVR-103 角色能力（v1，P0）

角色池与能力表（发牌后固定，全局无人出局、无技能重复触发）：

| 角色 | 阵营 | 能力 | 情报关系 |
|---|---|---|---|
| 梅林 Merlin | 好人 | 无主动技能；开局看到**除莫德雷德外**的全部坏人 | 被刺杀目标 |
| 派西维尔 Percival | 好人 | 无主动技能；开局看到梅林与莫甘娜（混排，不可分辨） | — |
| 忠诚仆从 Loyal Servant | 好人 | 无 | 无夜间情报 |
| 刺客 Assassin | 坏人 | 持刺杀权：刺杀环节执行指认（AVR-106） | 坏人互识（除奥伯伦） |
| 莫甘娜 Morgana | 坏人 | 在派西维尔视野中伪装成梅林 | 坏人互识（除奥伯伦） |
| 莫德雷德 Mordred | 坏人 | 对梅林隐形（梅林看不到他） | 坏人互识（除奥伯伦） |
| 奥伯伦 Oberon | 坏人 | 自己看到其他坏人，但其他坏人看不到他 | 单向情报 |
| 爪牙 Minion | 坏人 | 无 | 坏人互识（除奥伯伦） |

### AVR-104 队长轮转（v1，P0）

描述：每轮第 1 次提名前，轮值队长按座位 +1 轮转；同一轮内被拒后重新提案，队长同样轮转下一位。开局首任队长由种子随机决定。

验收标准：
- Given 任意新提案（无论同轮重提或新轮），Then 队长 = 上一位队长的下一位座位，且发出公共队长指定事件。
- Given 同一配置同一种子，Then 首任队长确定。

### AVR-105 队伍提名（v1，P0）

描述：轮值队长提名一支任务队伍：人数 = 本轮任务人数表值，成员为任意存活玩家（可含队长本人）。

验收标准：
- Given 队长在提名阶段提交恰好 N 名互异玩家的名单，Then 提案成立并公开，进入表决。
- Given 提名人数不符 / 重复 / 越界，Then 结构化拒绝。

### AVR-106 刺杀环节（v1，P0；全量化的核心增量）

描述：好人拿满 3 个任务成功后**不立即获胜**，进入刺杀环节：坏人阵营先进行秘密合议（仅坏人可见的发言轮，座位序每人一条），随后刺杀权持有者（刺客角色；若板子无刺客角色卡则由座位序第一名坏人代行）指认一名玩家。被指认者是梅林 → 坏人翻盘获胜；不是 → 好人获胜。

验收标准：
- Given 好人达成 3 个任务成功，When 任务结算完成，Then 阶段进入刺杀合议（仅坏人可行动），再进入刺杀指认（仅刺杀权持有者可行动）。
- Given 刺杀指认梅林，Then 坏人胜利，终局依据注明刺杀翻盘。
- Given 刺杀指认非梅林，Then 好人胜利。
- Given 指认目标为刺杀者本人 / 不在名册，Then 结构化拒绝。
- 坏人达成 3 个任务失败或触发连坐（AVR-403）时**无刺杀环节**，直接坏人胜利。

### AVR-107 表决公开性（v1，P0；口径变更）

描述：队伍表决为**公开记名投票**（标准桌面口径）：每名玩家的赞成 / 反对立场与身份一同公开。此为对冒烟规格「匿名计票」的显式口径变更——公开立场是好人推理与坏人伪装博弈的核心信息。

验收标准：
- Given 表决阶段每名玩家投票，Then 产生一条「投票人 + 立场」的公共事件。
- Given 全员投完，Then 公共汇总事件给出计数与结果（赞成严格多于反对 = 通过；平票 = 否决）。

### AVR-108 任务抉择保密性（v1，P0）

描述：任务成员的秘密抉择（成功牌 / 失败牌）对所有人保密（含上帝视角观众在终局前不可见个体立场）；任务结果只公布成功 / 失败与**失败牌张数**，不公布出牌人。好人在任务中**只能出成功牌**（引擎强制）；坏人在双失败轮之外任选、在双失败轮也任选（双失败约束只作用于任务结果判定，AVR-402）。

验收标准：
- Given 好人成员提交失败牌，Then 结构化拒绝（非法选择）。
- Given 任务结算，Then 结果事件含失败张数、不含出牌人身份。
- Given 单成员视角回看，Then 只能看到自己的抉择事件（role-self 受众）。

## 2. 信息可见性需求（AVR-2xx）

### AVR-201 事件受众标记（v1，P0）

每条事件必带受众标记：公共 public / 延迟公共 delayed-public（终局揭示类）/ 个人 role-self（发牌、情报、个人抉择）。受众标记是可见性的唯一真相，无标记即默认不可见。

### AVR-202 决策上下文由可见事件子集重建（v1，P0）

Agent 决策上下文 = 其可见事件子集的机械量投影 + 名册 + 板子参数。任何 Agent 不得经由决策上下文获得超出其受众的事件信息。

### AVR-203 夜间知识矩阵（v1，P0）

| 谁 | 看到 | 看不到 |
|---|---|---|
| 梅林 | 除莫德雷德外的全部坏人 | 莫德雷德 |
| 派西维尔 | 梅林与莫甘娜（混排） | 何者为真梅林 |
| 坏人（爪牙/刺客/莫甘娜/莫德雷德） | 除奥伯伦外的全部同伙 | 奥伯伦 |
| 奥伯伦 | 除自己外全部坏人 | （对方看不到他） |
| 忠诚仆从 | 无 | 一切身份 |

验收：Given 发牌完成，Then 每名玩家的知识以 role-self 事件下发且恰好符合矩阵；好人（除梅林/派西维尔）无任何身份情报事件。

### AVR-204 无越权输出（v1，P0）

引擎任何接口不得把私有受众事件的 payload 泄露给非受众（包括表决前他人的立场、任务抉择个体立场、发牌结果、随机种子在终局前）。

### AVR-205 观战与回放复用同一过滤口径（v1，P0）

上帝视角 = 全事件流；公开视角 = 仅公共 + 延迟公共；单玩家视角 = 该玩家可见子集。三口径同源于同一过滤函数。

## 3. 动作与校验需求（AVR-3xx）

### AVR-301 动作空间（v1，P0）

| 动作 | 行动者 | 阶段 | 参数 | 语义 |
|---|---|---|---|---|
| speak | 座位序逐人 | 讨论 | 文本（1–2000 字） | 公开发言（载荷透传，内容不入引擎判定） |
| proposeTeam | 轮值队长 | 提名 | targetIds（N 人） | 提名任务队伍 |
| vote | 全员逐人 | 表决 | approve: boolean | 公开记名表决 |
| quest | 队伍成员逐人 | 任务 | succeed: boolean | 秘密出牌（好人强制 true） |
| consult | 坏人逐人 | 刺杀合议 | 文本 | 仅坏人可见的秘密合议发言 |
| assassinate | 刺杀权持有者 | 刺杀指认 | targetId（1 人，非本人） | 指认梅林 |

### AVR-302 结构化拒绝（v1，P0）

所有非法动作返回结构化拒绝：错误码（阶段不符 / 行动者不符 / 目标非法 / 选择非法 / 参数冲突 / 不可解析）+ 人可读消息 + 上下文（轮次、阶段、行动者、动作类型）。

### AVR-303 别名归一（上游契约，v1，P0）

上游适配层把 LLM 的自然语言动作（中英文别名、字段名变体、布尔词表）归一到上述动作空间；归一失败给结构化不可解析拒绝。语境消歧以「当前合法动作类型集合」的交集为准。

### AVR-304 无响应默认动作（v1，P0）

任一待行动者超时 / 失败时，平台以默认动作推进，对局永不死锁：

| 动作 | 默认值 | 备注 |
|---|---|---|
| speak | 跳过（空发言事件，带默认标记） | 不伪造文本 |
| proposeTeam | 座位序下 N 名玩家（含轮转约定） | 确定性 |
| vote | 反对 | 保守口径（AVR-OD-2） |
| quest | 好人 true / 坏人 true | 保守口径：默认成功牌（AVR-OD-2） |
| consult | 跳过 | 同 speak |
| assassinate | 座位序第一名非本人玩家 | 确定性 |

默认动作事件必须带默认标记（观战可见兜底接管，FR-4.4-04）。

## 4. 状态推进与裁决需求（AVR-4xx）

### AVR-401 任务结算（v1，P0）

全队出牌后结算：失败张数 ≥ 阈值（普通轮 1 / 双失败轮 2）→ 任务失败；否则成功。结果记入战绩并公共公布。

### AVR-402 双失败轮（v1，P0）

按板子配置（标准：6 人以上板第 4 轮）。注意：双失败约束只提高**判失败所需张数**，不强制坏人出失败牌。

### AVR-403 连续拒绝连坐（v1，P0；口径变更）

同一轮内第 5 次提案被拒 → **坏人直接胜利**（任务不算失败、不进任务阶段）。此为对冒烟规格「第 3 次拒绝判该任务失败」的显式口径变更（标准口径）。

### AVR-404 终局裁决（v1，P0）

胜利条件优先级：坏人 3 任务失败 > 好人 3 任务成功（→ 刺杀环节裁决）> 连坐触发。终局事件（延迟公共）揭示全部身份 + 依据（任务比分或刺杀翻盘）。排名按阵营分组：胜方全员并列前段（组内按座位）、负方后段，平局不存在（规则保证必分胜负）。

### AVR-405 比赛永不死锁（v1，P0）

任何阶段任何待行动者都有默认动作（AVR-304）；强制终结接口给出按当前战绩的裁决（任务比分多者胜；0:0 时按平局处理并注明强制终结）。

## 5. 事件契约需求（AVR-5xx）

### AVR-501 事件 = 单一真相源（v1，P0）

追加式事实日志；每条含：序号（单调）、轮次计数、受众、行动者、事件类型、载荷；直接映射已提交动作的事件锚定原动作。状态可由事件流重放重建。

### AVR-502 最小事件集清单（v1，P0）

| 事件 | 受众 | 载荷要点 |
|---|---|---|
| matchStarted | public | 板子配置摘要、座位名册 |
| randomnessSeed | delayed-public | 种子 |
| rolesAssigned | role-self ×每玩家 | 角色 |
| knowledgeRevealed | role-self | 情报类型 + 指向玩家（混排不标注真伪） |
| phaseEntered | public | 阶段 |
| leaderAssigned | public | 轮次、提案序、队长 |
| statementIssued | public | 发言人、文本 |
| teamProposed | public | 轮次、提案序、队长、队伍（座位序） |
| voteCast | public | 投票人、立场 |
| voteResult | public | 计数、结果 |
| questChoice | role-self | 本人抉择 |
| questResult | public | 结果、失败张数 |
| evilConsultation | role-self（坏人受众逐人）* | 发言人、文本 |
| assassinationDeclared | public | 指认目标 |
| gameEnded | delayed-public | 胜方、依据、身份揭示 |

*evilConsultation：发言人本人受众的 role-self（坏人互见合议的实现 = 每条合议发给全部坏人各自 role-self 副本；或等价的坏人组受众——以实现体系为准，需求约束是「好人不可见、坏人间互见、上帝视角可见」）。

### AVR-503 可重放性（v1，P0）

Given 完整事件流（含种子），Then 重放结果与在线对局状态逐字段一致。

### AVR-504 事件不可变（v1，P0）

已入流事件不得修改或删除。

## 7. 非功能需求（AVR-Nxx）

| 编号 | 需求 | 验收 |
|---|---|---|
| AVR-N1 | 确定性重放 | 同配置 + 同动作序列 + 同种子 → 逐字段一致 |
| AVR-N2 | 知识隔离零泄露 | 对抗性测试：任意单玩家视角的事件子集不含越权信息 |
| AVR-N3 | 平台零侵入 | 全量接入不引入平台核心（GM / 调度 / 存储）的品类分支 |
