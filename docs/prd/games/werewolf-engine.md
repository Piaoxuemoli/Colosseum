## 0. 范围与定位

### 0.1 引擎是什么

狼人杀引擎是一个**纯逻辑规则机**，职责链路为：

**配置（板子）→ 初始局生成 → 合法动作校验 → 状态推进 → 事件流输出 → 终局裁决**

- 输入：板子配置 + 外部提交的动作序列（发言 / 投票 / 夜间技能等）。
- 输出：追加式事件流、可查询的对局态势（按受众口径）、终局结果（胜负阵营 + 可验证的过程依据）。
- 引擎是可独立验证的规则权威：同一配置 + 同一动作序列（+ 同一显式随机种子），永远得到同一结果（NFR-W1）。

### 0.2 引擎不是什么

| # | 不含 | 归属 |
|---|---|---|
| 1 | AI 策略、记忆、信念、发言文本生成 | Agent 侧；引擎只提供决策上下文与动作空间 |
| 2 | UI / 观战呈现 | 产品 PRD FR-4.5-02 |
| 3 | 主持人旁白 / 解说生成 | 产品 PRD FR-4.7；引擎只提供事实事件，旁白不得虚构（FR-4.7-02） |
| 4 | LLM 调用、超时重试 | 平台层；引擎只定义无响应时的默认动作契约（WFR-304） |
| 5 | 对局管理（创建 / 删除 / 结束控制） | 产品 PRD FR-4.3 |

### 0.3 与产品需求的衔接

- 引擎事件流是观战（FR-4.4）、回放（FR-4.6-02/03）、思考链日志与异常清单（FR-4.8-01/02）的数据地基。
- 引擎的配置驱动能力（WFR-101）是「品类即插件」（FR-4.5-03 / NFR-08）在狼人杀实例上的具体化，并为第三个游戏品类的接入框架决策（产品 PRD OD-1）提供引擎层参照。
- 分期沿用调研建议并按板子需求微调：**v1-M1**（配置驱动核心 + 6 人板 + 9 人 333 板，含猎人禁枪裁决）→ **v1-M2**（守卫 / 白痴 / 警长要素，衔接 12 人目标板）→ **v2**（自爆 / 第三方阵营 / 扩展角色）。

- Given 任意合法板子配置（人数与角色数量一致、参数在允许域内），When 用于开局，Then 引擎按配置生成初始局，不依赖引擎内置的特定人数或角色假设。

### WFR-102 阶段图驱动（v1-M1，P0）

描述：夜 / 昼阶段序列与角色行动顺序由板子配置声明，引擎按声明推进；行动顺序只影响信息可见性时序（如女巫何时获知刀口），不影响结算结果——夜间统一结算见 WFR-401。

需求：
1. 阶段图最小声明能力：每个阶段声明「类型（行动 / 公告 / 投票 / 结算）+ 参与角色 + 顺序 + 跳过条件」。
2. 无该角色则跳过：本局不存在该角色时其行动阶段自动跳过，不产生空等待与空槽位事件。
3. 公告类阶段显式化：平安夜公告、死讯 / 双死公告、猎人开枪许可是**显式阶段 / 显式事件**，不是其他阶段结算的附带副作用——公告本身是公共信息，必须进入事件流（支撑 FR-4.5-02「主持人宣告进入动作流」）。
4. 顺序无关性保证：任何合法夜间顺序下，同一动作集合的结算结果一致。

验收标准：
- Given 板子未配置守卫，When 夜晚推进，Then 直接进入下一行动阶段，全程无守卫阶段痕迹。
- Given 夜晚无人死亡（空刀 / 被救），When 白天开始，Then 产生显式「平安夜」公告事件（受众 = public）。
- Given 同一局分别按两种合法夜间顺序收集到同一动作集合，Then 结算结果与白天公告完全一致。

### WFR-104 警长系统（v1-M2；WOD-2 已代决 a——全流程随 M2 交付，板子默认开关仍为关）

描述：警长（Sheriff）是白天竞选产生的功能职位，非身份牌。完整流程：

1. **竞选**（仅首日）：上警 → 竞选演讲 → 退选（退选者丧失选举权；上警者无论是否退选均无选举权）→ 警下玩家投票 → 相对多数当选。
2. **平票**：PK 发言（后发言者先说）→ 警下再投 → 再平票则本局无警长。
3. **职权**：投票 1 票计参数 23 的权重；白天最后一个发言（归票权）。
4. **警徽流**：警长死亡时可将警徽移交给任意存活玩家，或撕徽（本局此后无警长）；「移交目标」必须是显式动作（支撑预言家警徽流玩法与观战叙事）。
5. **吞徽**：竞选阶段狼自爆则本局无警徽（依赖 v2 自爆动作；口径随参数 22 预留）。

## 2. 信息可见性需求（WFR-2xx）——本引擎的灵魂需求

### WFR-201 事件受众标记（v1-M1，P0）

每个事件必须携带受众标记（audience），取值域：`public`（全员）/ `wolves`（狼队）/ `role:self`（特定角色且仅本人，如预言家验人结果、女巫刀口告知）/ `sheriff`（警长）/ `moderator`（仅主持人）。缺失或非法受众标记的事件视为不合法事件，引擎不得产出。

### WFR-202 决策上下文由可见事件子集重建（v1-M1，P0）

Agent 的决策上下文只能由「该 Agent 可见的事件子集」重建，引擎提供按受众视角的过滤口径，绝不暴露全局内部状态。夜间知识隔离矩阵（调研 3.3 节，落成需求表；✓ = 可见）：

| 事件 | 狼队 | 预言家 | 女巫 | 守卫 | 猎人 | 村民 | 主持人 |
|---|---|---|---|---|---|---|---|
| 狼队成员与刀口目标 | ✓ | ✗ | ✗ | ✗ | ✗ | ✗ | ✓ |
| 守卫守护目标 | ✗ | ✗ | ✗ | ✓ | ✗ | ✗ | ✓ |
| 刀口是谁（救药决策前提） | ✓ | ✗ | ✓ | ✗ | ✗ | ✗ | ✓ |
| 女巫用药与否及目标 | ✗ | ✗ | ✓ | ✗ | ✗ | ✗ | ✓ |
| 预言家验人结果 | ✗ | ✓ | ✗ | ✗ | ✗ | ✗ | ✓ |
| 猎人能否开枪（毒死禁枪） | ✗ | ✗ | ✗ | ✗ | ✓ | ✗ | ✓ |
| 白天死讯（人数与座位） | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 死因（刀 / 毒 / 枪） | ✗ | ✗ | ✗ | ✗ | ✗ | ✗ | ✓ |
| 死者身份牌（暗牌局） | ✗ | ✗ | ✗ | ✗ | ✗ | ✗ | ✓ |
| 公开发言 / 投票 / 遗言 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

### WFR-203 关键信息流需求（v1-M1，P0）

1. **死因默认隐藏**：白天只公告死讯（人数与座位号），不公布死因、不翻牌（参数 9/10）。
2. **女巫刀口告知**：必须以独立的「刀口告知」事件（受众 = 女巫本人）在女巫行动前送达——这是标准规则下女巫决策的前提。
3. **预言家结果私有且二值**：仅本人可见，只有好人 / 狼人两值，不携带具体身份。
4. **猎人开枪许可**：死因对猎人也隐藏，「能否开枪」由主持人以私有事件（受众 = 猎人本人）裁决告知。
5. **狼队互识**：首夜起狼队成员互相可见。

### WFR-204 无越权输出（v1-M1，P0）

引擎不得在任何公开或受限事件中携带超出其受众标记的信息——包括但不限于：死因、底牌、刀口、验人结果的精确身份、内部结算中间量、调试字段。验收以第 9 节自动审计用例（AC-13）为准。

### WFR-205 主持人视角（v1-M1，P0）

主持人（产品侧 AI 调度 / 解说）可见全量事件；但引擎事件契约必须区分「公开播报」（死讯、平安夜等，受众 = public）与「私下确认」（猎人开枪许可等，受众 = role:self），使主持人产出天然携带受众标注，不越权播报（衔接 FR-4.7-01「旁白只引用公开信息」）。

### WFR-206 观战与回放复用同一过滤口径（v1-M1，P0）

观战上帝视角 = 全量事件；单 Agent 视角（回放、思考链日志、选手视角检视）= 与对局内同一套受众过滤。两口径对同一事件流的过滤结果必须一致（支撑 FR-4.6-02/03 与「决策标本」定位）。

| 放逐投票 | 存活且有票权者 | 处于投票阶段；目标为存活者或弃票；白痴翻牌后无票权 | M1 |
| 开枪 | 死亡结算中的猎人 | 处于开枪窗口；死因允许（参数 16/17）；次数未用；可放弃（憋枪） | M1 |
| 守护 | 存活守卫 | 处于守护阶段；目标为存活者（含自己）；非上晚同目标（参数 18） | M2 |
| 翻牌（白痴） | 被放逐的白痴 | 处于放逐结算；次数未用 | M2 |
| 上警 / 退选 | 任意存活者 | 处于竞选对应子阶段；退选后不可再上 | v2 |
| 警长竞选投票 | 警下存活者 | 未上警、未退选；仅能投竞选者 | v2 |
| 警徽移交 / 撕徽 | 死亡中的警长 | 警长身份；移交目标为存活者 | v2 |
| 自爆 | 存活狼 | 处于白天发言阶段 | v2 |

### WFR-302 结构化拒绝（v1-M1，P0）

对非法动作，引擎必须返回结构化拒绝原因：错误类别（非法阶段 / 非法主体 / 非法目标 / 次数耗尽 / 参数冲突 / 不可解析）+ 可读描述 + 相关时序上下文。非法动作不产生任何状态副作用；拒绝记录可被上层留痕（衔接产品 PRD FR-4.4-04 错误与兜底可见性、FR-4.8-01 异常清单）。

### WFR-303 动作契约与别名归一（上游契约，v1-M1，P0）

引擎发布机器可读的动作空间声明（每个动作的参数、合法条件摘要、当前可提交性），供上游 Agent 适配层把 LLM 的自然语言输出（「毒 3 号」「用解药救他」等同义表述）归一为标准动作；引擎只对标准动作做终审。别名归一本身不在引擎内实现，但动作契约的完备性由引擎需求保证。

### WFR-304 无响应默认动作（v1-M1，P0）

每个需要行动的槽位必须定义超时 / 无响应时的默认动作（如：弃票、不发言占位、不使用技能、不守护），保证对局在该参与者缺位时仍按规则推进（衔接产品 PRD 兜底策略概念与 NFR-04「LLM 失败不终局」）；默认动作的发生在事件流中可辨识。

## 4. 状态推进与裁决需求（WFR-4xx）

### WFR-401 夜间统一结算（v1-M1，P0）

夜间采用「收集动作 → 统一结算」模型：先收集全部夜间动作（按声明顺序唤醒只决定信息送达时序），再按 WFR-402 裁决表一次性结算，产出死讯。禁止「边行动边结算」。

### WFR-402 夜间冲突裁决表（v1-M1 起，P0）

| 情形 | 裁决（默认口径） |
|---|---|
| 狼刀 + 守护 | 目标不死 |
| 狼刀 + 解药 | 目标不死 |
| 狼刀 + 守护 + 解药（同守同救 / 奶穿） | 目标死（参数 19） |
| 毒药 + 守护 | 目标死（毒穿，参数 20） |
| 狼刀与毒药指向不同目标 | 双死，公告死讯不公布死因 |
| 狼刀与毒药指向同一目标 | 目标死（一次） |
| 空刀 | 平安夜 |
| 自刀 | 按狼刀正常结算 |

### WFR-403 白天流程（v1-M1，P0）

固定流程：死讯公告（平安夜 / 单死 / 双死，不含死因）→ 夜死者遗言（按 WFR-105 矩阵）→ 存活者按顺序策略（参数 13）发言（无警长时从死者下一位起；首日无死者时自 1 号座位起——WOD-7 已决 a，可配置覆盖）→ 放逐投票（同时投、可弃票、相对多数、票权加权与剥夺）→ 平票处理（参数 7：平票者 PK 发言 → 全场再投（仅限 PK 者）→ 再平票则本轮无人出局，入夜）→ 放逐者遗言 → 入夜。

### WFR-404 死亡连锁与结算时序（v1-M1，P0）

1. 猎人开枪窗口：白天死即时开枪；夜间死在次日死讯公告后开枪。
2. 枪杀目标的死亡时间与开枪者同步（决定其遗言有无，见 WFR-105）。
3. 白痴翻牌结算优先于放逐出局（M2）。
4. 每次死亡结算后立即评估终局（WFR-405）；连锁死亡（枪带人、殉情）逐环结算直至无新死亡。

### WFR-405 终局裁决（v1-M1，P0；第三方 v2）

| 模式 | 狼人胜利 | 好人胜利 |
|---|---|---|
| 屠边（kill-side） | 杀光所有神职 **或** 杀光所有平民（任一边） | 放逐 / 消灭所有狼人 |
| 屠城（kill-all） | 杀光所有好人 | 消灭所有狼人 |
| 屠城 + parity | 存活狼数 ≥ 存活好人数（快判） | 消灭所有狼人 |

- **狼刀在先**（参数 3）：同一次结算中狼人达成胜利与好人达成胜利同时成立时，判狼人胜。
- 第三方阵营（丘比特链）胜利判定为 v2（WOD-6）。

### WFR-406 比赛永不死锁（v1-M1，P0）

1. 防死锁天数上限（参数 14）到达时，按配置的兜底裁决给出终局（不得无限推进）。
2. 全员死亡、或当前阶段所有参与者均无法 / 无需行动时，引擎必须强制推进到下一阶段或终局，不产生永久等待。

## 5. 事件契约需求（WFR-5xx）

### WFR-501 事件 = 单一真相源（v1-M1，P0）

事件是对局的事实日志：观战、回放、Agent 上下文重建、终局验证共用同一事件流；态势是事件流的投影，不得存在只存在于态势而不在事件流中的规则事实。

### WFR-503 可重放性（v1-M1，P0）

Given 完整事件序列，When 重放，Then 可完整重建对局任意时刻的态势、任意受众的视图与终局结果（支撑 FR-4.6-02「回放不重算、不改写」）。对局中的全部随机性（发牌等）必须以显式种子或结果事件进入事件流。

### WFR-504 事件不可变（v1-M1，P0）

事件流为追加式；已产出事件不可修改、不可删除；终局揭示（#19）前，任何事件不得提前泄漏终局才知道的信息。
