## 1. 页面目标与成功指标

大厅首页是全平台的默认入口，同时服务三类 persona：P3 娱乐观众要"一眼看懂、马上开看"，P1 研究者与 P2 学习者要"快速进局、快速组局"。首页的第一职责是回答三个问题：这是什么平台？现在有什么可看？我下一步该做什么？

| # | 目标陈述 | 验收口径 |
| --- | --- | --- |
| G1 | 5 秒理解：新用户（含 P3 娱乐观众）打开首页 5 秒内能说出"这是一个看 AI 互相博弈的平台" | 首屏可见：平台名称 + 一句话价值主张（PRD 1.1 愿景的人话转译，不堆术语）+ 至少一个"AI 博弈"具象线索（直播卡片或新手引导卡） |
| G2 | 30 秒行动：用户从首页出发，30 秒内到达"开始观战"或"创建对局"其一 | 有进行中对局时 ≤2 次点击进入观战页；无进行中对局时 ≤2 次点击到达创建对局流程或其前置引导 |
| G3 | 老用户直达：回访用户不翻页、不搜索即可定位自己关心的对局 | 自己创建/参与的进行中对局在直播区置顶或带"我的"标识；最近对局区在首屏至多 1 次滚动内可达 |
| G4 | 状态透明：不离开首页即可判断平台当前有无内容可看 | 运行中对局数常驻可见且与真实状态一致；获取失败时呈现"未知"而非 0 |
| G5 | 引导不断链：新手按首页引导走完 无 Profile → 无 Agent → 可组局 前置链，全程无裸报错 | 三个前置状态各有明确的下一步主行动与引导文案（承接 FR-4.1-01 空状态验收口径与 FR-4.2-02 模板库起步路径） |

## 2. 信息架构

页面自上而下按优先级排列为五个区块。整体骨架遵守 design-system 3.1 全局骨架（左侧窄导航 + 主内容区）；首页不使用观战页专属的顶部对局状态条与右侧面板：

```
┌──┬─────────────────────────────────────┐
│  │ 2.1 顶部区域（平台识别 + 全局状态）   │
│侧│ 2.2 正在直播区（进行中对局卡片网格）  │
│导│ 2.3 快速开始区（状态感知的创建引导）  │
│航│ 2.4 最近对局区（历史列表 + 回放入口） │
│  │ 2.5 次级导航（Profile / Agent 入口） │
└──┴─────────────────────────────────────┘
```

区块渲染顺序即优先顺序：直播区永远先于历史区出现；任一区块加载失败不得阻塞其下区块的渲染。

### 2.1 顶部区域（P0）

| 项 | 需求 |
| --- | --- |
| 目的 | 平台识别与全局状态一屏可见，服务 G1 / G4 |
| 内容项 | ① 平台名称（标题级字号）；② 一句话 slogan：人话表达"看 AI 如何思考与博弈"，不用术语堆砌；③ 全局状态：当前运行中对局数（等宽数值级 `--text-metric`），点击锚定滚动至直播区 |
| 交互 | 运行中数 > 0 时数字旁附进行中徽章（`--color-info`）；= 0 时弱化呈现 0，不隐藏；点击数字滚动定位到 2.2 |
| 空态 | 全新用户：slogan 旁可附一句欢迎文案；运行中数显示 0 |
| 加载态 | 数字显示骨架占位（约 8 字符宽），不得用 0 占位 |
| 优先级 | P0 |

### 2.2 「正在直播」区（P0）

| 项 | 需求 |
| --- | --- |
| 目的 | 运行中对局的实时入口，首页第一行动区，服务 G2 / G3 |
| 内容项 | 区块标题（含计数"正在直播 · N"）+ 卡片网格。每张卡片必须呈现六项要素：① 游戏品类（图标+文字 Tag）；② 局名；③ 进行阶段/手数（如"第 12 手 · 翻牌前"/"第 3 夜"）；④ 参赛 Agent 阵容（头像列 + 名称，淘汰态置灰，复用 Agent 头像组件的状态语义）；⑤ 观战热度概念（最低形态为"直播中"呼吸点徽章；若部署形态支持多观众则显示人数——OD-2 / OD-3 已代决单机无登录 + 仓库保持私有，多观众人数口径继续后置）；⑥ 进入观战主 CTA |
| 交互 | 卡片整体可点击进入观战页；阶段/手数与热度等实时字段按 design-system 第 6 节节奏批量合并更新（100-150ms 窗口合并渲染），不逐事件抖动；新对局开始时卡片以列表项进入动效（`--motion-fast`）插入，不改变用户当前滚动位置 |
| 空态 | 无进行中对局：显示引导卡（空态组件"首次空"形态），一句说明 + 主行动指向 2.3 快速开始；不得呈现空白网格 |
| 加载态 | 卡片形态骨架屏（微光动画），数量与网格列数一致，不超过 8 张 |
| 优先级 | 六项卡片要素与 CTA 为 P0；热度显示多观众人数口径为 P2 |

补充状态语义：对局终局结算时，卡片状态从"进行中"切换为"已结束"并迁移至最近对局区（迁移有 200-300ms 过渡，不瞬间消失）；卡片可带连接状态徽章三态（正常 / 降级重连中 / 失联），与 design-system 第 6 节一致。

### 2.3 「快速开始」区（P0）

| 项 | 需求 |
| --- | --- |
| 目的 | 创建对局主 CTA 的呈现层次 + 新手前置链引导（FR-4.1 → FR-4.2 → FR-4.3 依赖链的状态感知），服务 G2 / G5 |
| 内容项 | 一个突出的"创建对局"按钮 + 一段随用户资产状态变化的引导文案与子行动。状态感知矩阵见下表 |
| 交互 | 按钮永远可见；其层级与去向随状态变化，任何状态下点击都有明确去处，不允许点击无响应或裸报错 |
| 空态 | 见状态矩阵 S0 |
| 加载态 | 用户资产状态（有无 Profile / Agent）判定完成前，引导区显示一行骨架；按钮保持可点击但跳转至安全引导页 |
| 优先级 | P0 |

状态感知矩阵（文案为示意，验收看行为）：

| 状态 | 判定 | 按钮呈现 | 引导要点 |
| --- | --- | --- | --- |
| S0 无 Profile | 无任何 LLM Profile | "先配置模型 Key"主行动 + "创建对局"次级 | 说明参赛 Agent 依赖模型接入，直达 Profile 创建；承接 FR-4.1-01 空状态引导验收 |
| S1 有 Profile、无 Agent | 有 Profile 且无任何 Agent | "从模板创建 Agent"主行动 + "创建对局"次级 | 引导用预置人设模板零创作起步（FR-4.2-02），说明组局先要有选手 |
| S2 可组局 | 存在可用 Profile 与足量 Agent | "创建对局"主按钮（主色、放大层级） | 直达创建向导；人数不满足时由向导校验指出具体缺口（FR-4.3-01） |
| S2′ 部分可用 | Profile 失效或可用 Agent 数量不足 | "创建对局"次级 + 一行警示 | 引用失效 Profile 时赛前必须警示或阻断并给出修复入口（FR-4.1-03），不允许静默依赖兜底开局 |

### 2.4 「最近对局」区（区块 P0；过滤与管理 P1）

| 项 | 需求 |
| --- | --- |
| 目的 | 已完成对局的前置呈现，是 FR-4.6-04 对局历史列表在首页的缩影：看结果、进回放、管资产 |
| 内容项 | 区块标题 + 历史卡片/行列表。每条必须含：① 游戏品类 Tag；② 局名与结束时间（相对时间，悬停显绝对时间）；③ 时长；④ 终局排名摘要（冠军 Agent 头像 + 名次序列，名次数字等宽）；⑤ 回放入口按钮；⑥ 主人操作：删除（二次确认，确认文案明示不可恢复，承接 FR-4.3-04）。过滤在首页仅保留品类快速过滤；完整过滤（品类/时间/Agent）由历史列表页承接 |
| 交互 | 点击条目进入结算页；"回放"直达回放页；删除走对话框危险变体，确认后条目以退出动效移除并同步计数 |
| 空态 | 全新用户：说明文案 + 指向 2.3 的主行动；有直播但无历史：文案区分"还没有已结束的对局" |
| 加载态 | 行骨架，首批固定 6-8 条 |
| 加载方式 | 滚动加载：触底加载下一批（每批 8-12 条），加载中显示底部行骨架；首页最多自动加载 3 批，之后提供"查看全部对局"入口跳转历史列表页，避免首页无限滚动 |
| 优先级 | 区块、结果摘要与回放入口 P0；删除管理 P1；品类快速过滤 P1 |

### 2.5 次级导航区（P1）

| 项 | 需求 |
| --- | --- |
| 目的 | 露出去管理 Profile / Agent 的入口，但不与主行动争夺注意力 |
| 内容项 | 两个文字级入口（线性图标 + 文字链接）："管理模型 Profile"、"管理 Agent"；可附一行状态警示（如"1 个 Profile 失效"，`--color-warning`），警示行可点击直达修复 |
| 交互 | 悬停微交互（`--motion-instant`）；点击进入对应管理页 |
| 空态 | 无资产时入口保留，文案换为"去创建第一个…" |
| 加载态 | 无独立加载态，随区块渲染 |
| 优先级 | P1（常驻导航本身已由左侧导航承载，本区是首页内的补充露出，不喧宾夺主） |

## 3. 关键交互流程需求

首页是三条主流程的起点。以下按步给出反馈要求；"骨架"一律指 design-system 4.1 骨架屏组件（卡/行形态）。

### 3.1 进入观战

| 步骤 | 反馈要求 |
| --- | --- |
| 点击直播卡片 / CTA | 按压即时反馈（≤ `--motion-instant`）；跳转期间 CTA 进入加载态，防止重复触发 |
| 观战页加载 | 首屏 ≤ 3 秒呈现当前态势（NFR-01）；加载期呈现态势骨架而非白屏 |
| 对局在跳转途中结束 | 不报错：进入后落在结算页，并提示"对局刚刚结束" |
| 实时性 | 动作发生到观众可见端到端 ≤ 2 秒（NFR-03，不含 LLM 思考时长）；连接状态徽章三态可见 |

### 3.2 创建对局

| 步骤 | 反馈要求 |
| --- | --- |
| 点击"创建对局" | 按状态矩阵（2.3）决定去向：直接进向导，或先进前置引导页；任何状态不出现裸报错 |
| 进入创建向导 | 遵守 design-system 3.3 向导契约（左侧分步表单 + 右侧实时预览）；人数不满足时提交被拦截并指出具体缺口（FR-4.3-01） |
| 引用失效 Profile | 赛前警示或阻断，附"更换 Key"入口（FR-4.1-03），不允许静默兜底开局 |
| 创建成功 | 进入对局页完整展示阵容、规则摘要与开始入口（FR-4.3-01 验收口径）；返回首页时直播区可见新对局卡片 |

### 3.3 查看回放

| 步骤 | 反馈要求 |
| --- | --- |
| 点击"回放" | 按压反馈；回放页加载期呈现骨架（赛场区 + 进度条占位） |
| 回放数据就绪 | 可拖动到任意时间点并正确重建该时刻态势；阶段列表完整无遗漏（FR-4.6-02） |
| 条目打开失败 | 给出可读错误空态与"返回大厅"行动，不白屏 |

## 4. 布局与视觉要求

1. **骨架**：遵守 design-system 3.1 全局骨架——左侧窄导航（56px，悬停/聚焦展开 240px；导航项：大厅、对局列表、Profile 管理、排名、设置）+ 主内容区；首页不出现观战页专属的顶部状态条与右侧面板。
2. **卡片网格**：直播区与最近对局区采用卡片栅格 `auto-fill, minmax(320px, 1fr)`（design-system 3.3 大厅契约）；卡片为第一层表面 `--color-bg-1`、`--radius-md`、1px 边框，hover 浮起至第二层语义（阴影 `0 4px 16px rgba(0,0,0,.35)`）；卡片内边距 `--space-3` ~ `--space-4`。
3. **暗色控制台氛围在首页落地**：页面底用 `--color-bg-canvas`，卡片/区块表面用 `--color-bg-1`；文字三级严格分工（区块标题=标题级、卡片元信息=辅助级、时间戳=微缩级）；运行中数、手数、名次等数字一律等宽字体。首页**不使用**思考链专属紫（首页无思考链场景，"看到紫 = AI 在想"的条件反射不得被稀释）；品类识别用图标+文字 Tag，不用场景色渲染卡片本体——场景色保留给观战页赛场氛围。
4. **首屏信息密度**：桌面（≥1280px）100dvh 内完整可见：顶部区域、快速开始区、直播区标题与至少一行卡片（或空态引导卡）。密度对标"信息密度优先于留白"原则，但允许比观战页多一档留白以服务 G1 的 5 秒理解：区块之间用 `--space-8` 分隔，区块内部维持紧凑密度（控件 28-32px 高、列表行高 36-40px）。
5. **动效预算**：首页常驻动效仅三处——直播呼吸点、卡片 hover 浮起、新卡片进入；全部落在 design-system 时长阶梯内并支持 `prefers-reduced-motion` 降级。

## 5. 状态与边界需求

### 5.1 空态：全新用户零数据
- 首页任何情况下不出现整页空白：无 Profile、无 Agent、无对局时，页面仍完整呈现顶部区域 + 快速开始区（S0 引导）+ 直播区与最近对局区各一张空态引导卡。
- 空态文案区分"首次空"（还没发生过）与"过滤后空"（该品类暂无），各配一句引导文案与一个主行动按钮（空态组件契约）。
- 全新用户的首屏视觉焦点必须是快速开始区，不得被空态卡淹没。

### 5.2 错误态：API 失败
- 区块级隔离：任一区块数据获取失败只影响该区块，呈现错误空态（图标 + 一句原因 + 重试按钮），其余区块正常渲染。
- 全局状态（运行中对局数）失败时显示"未知"占位与重试入口，禁止显示 0（避免误导"平台无对局"）。
- 重试成功后原地更新，不整页刷新。

### 5.3 多对局长列表上限
- 直播区首屏最多渲染 8 张卡片；超出部分提供"查看全部 N 场"入口进入对局列表页。
- 排序：进行中对局按最近一次动作时间降序；用户自己创建的对局置顶并带"我的"标识（服务 G3）。
- 卡片实时更新遵守批量合并节奏；同时活跃的卡片动画数量有节制（design-system 第 5、6 节）。

### 5.4 移动端降级（<768px）
- 单栏堆叠，区块顺序不变；左侧导航按 design-system 断点策略降级（折叠或底部形态），"创建对局"入口必须仍一步可达。
- 顶部区域压缩：保留平台名 + 运行中数，slogan 可省略。
- 卡片单列全宽；卡片内阵容头像列允许横向滚动；触控目标放大（≥44px），桌面紧凑密度不适用于触控。
- 允许整页滚动（移动端豁免一屏原则，与 design-system 3.1 一致）。

## 7. 验收标准（清单式）

- [ ] 首屏（桌面 ≥1280px）可见：平台名、slogan、运行中对局数、快速开始区、直播区（或其空态卡），无需整页滚动。
- [ ] 5 秒理解测试（G1）：新用户不看文档能复述"这是看 AI 博弈的平台"。
- [ ] 有进行中对局时 ≤2 次点击进入观战页；无对局时 ≤2 次点击到达创建对局或其前置引导（G2）。
- [ ] 每张直播卡片呈现六项要素：品类 Tag、局名、阶段/手数、Agent 阵容（淘汰置灰）、观战热度概念、进入观战 CTA。
- [ ] 快速开始区四状态（S0 / S1 / S2 / S2′）逐一触发验证：主行动去向正确、无裸报错、失效 Profile 有赛前警示路径。
- [ ] 全新用户零数据首屏：空态引导卡齐全且视觉焦点在快速开始区；空态文案区分首次空 / 过滤后空。
- [ ] 任一区块 API 失败：仅该区块呈错误空态 + 重试；全局状态数显示"未知"而非 0；重试原地恢复。
- [ ] 直播区超过 8 场时：首屏渲染 8 张 + "查看全部"入口；用户自己的对局置顶并带"我的"标识（G3）。
- [ ] 最近对局条目含品类、结束时间、时长、排名摘要、回放入口；删除有二次确认且文案明示不可恢复。
- [ ] 滚动加载：触底加载下一批，自动加载最多 3 批后出现"查看全部对局"入口。
- [ ] 卡片实时字段批量合并不抖动；新对局插入不改变滚动位置；对局结束时卡片迁移至最近对局区且有 200-300ms 过渡。
- [ ] 视觉合规：颜色 / 字号 / 间距全部来自 tokens；数字等宽；首页无思考链紫、无场景色渲染卡片；卡片网格为 `auto-fill, minmax(320px, 1fr)`。
- [ ] 无障碍：正文对比度 ≥ 4.5:1；全部操作键盘可达且焦点环可见；颜色不是唯一信息载体（进行中 / 已结束有文字并行标识）。
- [ ] 移动端（<768px）：单栏堆叠、卡片单列、触控目标 ≥ 44px、创建入口一步可达、允许整页滚动。
