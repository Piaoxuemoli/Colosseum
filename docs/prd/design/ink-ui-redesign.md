## 1. 目标与边界

**目标**：把「arena 控制台」风格全站替换为 design-system v2.0 的水墨体系；同时重设计前端交互（不是换肤——信息架构与组件形态按 §3 重排）；把 A2UI 声明式路径的适配点一次性梳理清楚，为后续纳入重构范围做好接口预留。

**边界（本轮不做）**：不写任何生产代码；不改后端与引擎；不新增页面路由（信息架构沿用现有五区/三栏骨架）。

## 2. 页面清单与重设计要点

### 2.1 大厅首页

沿袭五区信息架构（顶部 / 直播 / 快速开始 / 最近对局 / 次级导航），视觉与交互重排：

| 区 | 重设计要点 |
| --- | --- |
| 顶部 | 品牌区改为书法体「竞技场」题字 + 竖排副题「观 AI 博弈 · 品墨局千变」；运行中数改「擂台 N 局」+ 墨滴呼吸指示 |
| 直播区「今日擂台」 | 标题带品类印章行（德/狼/瓦三小章）；卡片 = 册页式 InkPanel：品类印章 + 书法体局名 + 阶段进度（等宽）+ 阵容头像列（圆形墨框）+「入局」朱砂幽灵按钮；新卡片 InkRipple 进入 |
| 快速开始 | 状态感知引导保留 S0/S1/S2/S2′ 矩阵；卡片画框式（双钩 + 按当前品类变奏晕）；主 CTA 朱砂印章式按钮「开 局」 |
| 最近对局 | 行高 44px；品类印章 + 相对时间（等宽）+ 排名摘要（冠军带小胜章）+「回放」墨线按钮 |
| 次级导航 | 笔触分隔下的文字链接行 |

### 2.2 组局配置（/matches/new）

- 三品类 tab 改为**三枚印章 tab**（德/狼/瓦，选中 = 朱砂底反白，未选 = 墨线章）；切换时预览区变奏晕切换。
- 表单：分步式保留；预设/参数控件 token 换血；选中 Agent 的席位卡 = 画框小卡（头像 + 名 + 移除「×」笔锋）。
- keyring 检查面板（KeyGatePanel）视觉换血，交互不变（赛前阻断逻辑是已验收行为，不动）。
- 提交按钮 = 朱砂大印「开 局」，落定动效 StampReveal 后跳转。

### 2.3 观战页（核心，三游戏变奏）

通用骨架（三栏 + 底部回放条）沿袭，视觉与交互按 design-system §3.2/§7：

| 区 | 重设计 |
| --- | --- |
| 赛场区顶部 | 游戏题款：竖排书法体游戏名 + 变奏印章 + 阶段条（变奏色） |
| 态势面板 | 各游戏专属件水墨化（德扑青花牌桌/筹码瓷片；狼人夜月座位/月相；阿瓦隆册页任务板/鎏金令章） |
| 思考链 | 花青晕气泡 + 书法体摘要 + 等宽原文；「思考中」墨滴呼吸 |
| 动作流 | 笔触连接线时间线；发言类条目书法体；胜负关键节点带小印章 |
| 视角切换 | 上帝/公开/选手三视角切换保留；切换器为三枚小章 |

### 2.4 回放页

观战骨架复用 + 底部控制条水墨化（进度条 = 一笔墨锋，阶段锚点 = 小墨点）；跳转锚点交互不变。

### 2.5 统计（/stats）

ELO 天梯 = 「墨榜」：名次用书法体大字（一/二/三…或甲/乙/丙），评分等宽；品类 tab 三章切换；用量面板 token 换血。

### 2.6 Agent / Profile 管理

列表行 44px + 墨线分隔；编辑对话框双钩 + 宣纸标题带；头像 = 圆形墨框。交互链路不变。

## 3. 交互链路重设计（全站规则）

1. **印章即状态**：品类、胜者、进行中、我的对局——凡「身份/终态」类信息优先用印章表达（带文字，满足无障碍）。
2. **墨晕即进行**：一切「正在发生」（直播、思考、等待行动）用墨滴呼吸或墨晕表达；静止信息不用循环动效。
3. **朱砂即行动**：每屏最多一个朱砂主按钮；危险操作（删除/强制终局）朱砂但需二次确认（对话框）。
4. **入画动效**：路由切换时主内容区 240ms 墨晕展开（配合 next.js 过渡）；观战页阶段切换 300ms 变奏晕扫。
5. **数值墨闪**：筹码/ELO/事件数变化 240ms 高亮渐隐（花青=获得，朱砂=损失）。
6. **空态**：书法体一句意境文案 + 一个主行动（如直播区空态：「棋盘已设，静候诸君——」+「开局」按钮）。
7. **键盘与快捷键**：现有快捷键体系（g h/g a/g p/n/?）全量保留；焦点环 = 墨线双环。

## 4. A2UI 适配梳理（核心增量）

### 4.1 现状基线（2026-09-10 核实）

官方渲染器 `@a2ui/react@0.10` + 自有 `colosseumCatalog`（官方组件 + AgentPicker/KeyCheckPanel 两个 stub）；德扑组局面已有声明式 surface（9 组件）；playground 在 `/a2ui-playground`；kill-switch `NEXT_PUBLIC_A2UI_CONFIG` 默认关；A2UI 路径缺 keyring 上传链路。

### 4.2 主题化机制结论

A2UI 的「你的设计系统才是重点，catalog 只是契约」是官方定位——**所有组件渲染都经我们的 catalog 实现层**，因此水墨化 = catalog 组件实现消费 design-system v2 tokens，**不依赖官方库提供任何主题能力**。官方组件与自定义组件同源继承水墨皮肤。

### 4.3 适配点清单（重构时的接口预留）

| # | 适配点 | 内容 | 优先级 |
| --- | --- | --- | --- |
| A1 | catalog 组件水墨化 | 官方组件包装层全量替换为水墨 tokens（按钮/输入/文本/行/列容器）；`colosseumCatalog` 成为水墨主题的第一公民消费方 | P0（与基础件同步） |
| A2 | SealBadge 进 catalog | 印章徽章注册为自定义组件（`component: "SealBadge"`），surface JSON 可直接声明品类章/胜章 | P1 |
| A3 | AgentPicker 实现 | 从 stub 升级为真实组件：席位卡（画框式）+ 墨线多选 + 人数联动；数据接口与现有表单共用 | P1 |
| A4 | KeyCheckPanel 实现 | 从 stub 升级：接入 keyring 健康链路（四态模型已验收），**补齐 A2UI 路径的 keyring 上传缺口**——这是 A2UI 能否转正的前提 | P1 |
| A5 | 三游戏 surface 化 | 狼人/阿瓦隆组局面各出 `.a2ui/surface/` 声明（对齐新交互稿的水墨组件）；德扑 surface 同步更新 | P2 |
| A6 | playground 水墨化 | `/a2ui-playground` 随 catalog 自动继承 | P2（零成本） |
| A7 | 转正评估门 | A1-A4 完成后：开 kill-switch 灰度 → 对比传统表单功能面（keyring 上传/阻断/人数联动全通）→ 达标后 A2UI 成为默认路径，传统表单退役 | P2（依赖 A4） |

### 4.4 决策约束

A2UI 与传统表单在重构期**双轨并行**：传统表单先水墨化（P0 主路径），A2UI 适配按上表推进；kill-switch 保持默认关，直到 A7 转正门通过。

## 5. 迁移策略（实现期参考）

顺序：① tokens 全量替换（一次 commit，全站即刻换基底）→ ② 基础件 + 水墨新增件 → ③ 大厅/配置/列表/管理页 → ④ 观战通用件 + 回放 → ⑤ 三游戏变奏（各一局真实验收）→ ⑥ A2UI catalog 换血（A1-A4）→ ⑦ 走查 + `npm run check` 每步门禁。回滚策略：tokens 层单 commit 可整体回退。

- [ ] `npm run check` 全绿；既有 663 测试中涉及 UI 文案/类名的断言同步更新。
