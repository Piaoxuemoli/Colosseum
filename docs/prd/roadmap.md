# Colosseum 交付路线图（Roadmap）

## 说明

- 本路线图从 PRD（`docs/prd/PRD.md`）功能清单导出，是**唯一排期权威**；PRD 变更若影响本文件条目，须同步更新。
- 每个大项（R1–R4）含：目标、优先级、验收口径（引用 PRD 的 FR / NFR 编号）、依赖关系；条目为可独立验收的任务单元。
- 勾选标准：所引用 FR / NFR 的验收标准全部可验证通过，且不引入新的 P0 缺陷。
- 顺序原则：R1 未完成不进入 R2 主体；R3 / R4 不得挤占 R2 的 P0 验收。
- 外部引用：`docs/research/`（CI 与测试体系调研报告 `2026-09-ci-test-survey.md`，给出 / 将给出方案）；`docs/repair/`（审计 `2026-09-audit.md`，问题编号 01–18）。
- 本文件只管排期与验收对照，不承载需求定义；需求争议以 PRD 为准。

### 总览

| 阶段 | 主题 | 优先级 | 退出条件（下阶段进入门槛） |
|---|---|---|---|
| R1 | 质量地基 | P0 | CI 门禁生效；测试体系可跑；审计 P0 / P1 缺陷清零或降级登记 |
| R2 | 核心体验补全 | P0 | 两个现有游戏的 P0 FR 验收全部通过（含真实 LLM 全链路） |
| R3 | 体系升级 | P1 | 呈现契约与接入框架经新品类冒烟验证；P1 增强面达标 |
| R4 | 扩展 | P2+ | 无统一退出条件；逐项依赖对应 OD 拍板后展开 |

## R3 体系升级（P1）

| 项 | 内容 |
|---|---|
| 目标 | 从"两个游戏"升级为"可扩展品类平台"，补齐 P1 增强面 |
| 依赖 | R2（核心 P0 体验达标） |
| 验收口径 | FR-4.5-03；NFR-08；FR-4.7-01 / 02；FR-4.6-05；FR-4.8-03（NFR-06） |

- [ ] **R3-1 呈现契约抽象**：将牌桌类 / 社交推理类共同满足的呈现要求收敛为品类呈现契约（态势视图、事件流、阶段模型、结算结构）（FR-4.5-03 前半）。
- [ ] **R3-2 新游戏接入框架**：以契约接入一个简化或改造版新品类做冒烟验证，不改平台核心（FR-4.5-03 后半、NFR-08；正式第三游戏依赖 OD-1，属 R4）。
- [ ] **R3-3 AI 主持人旁白增强**：关键事件旁白、仅公开信息约束、可关闭（FR-4.7-01）。
- [ ] **R3-4 赛后解说**：基于真实对局数据的终局解说，不虚构事件（FR-4.7-02）。
- [ ] **R3-5 跨对局画像（观众面）**：FR-4.6-05 统计聚合先行；Agent 决策用画像机制与 OD-5 联动后再启动。
- [ ] **R3-6 用量可见**：FR-4.8-03 按选手 / 用途聚合的 token 用量与调用次数（承接 NFR-06）。
