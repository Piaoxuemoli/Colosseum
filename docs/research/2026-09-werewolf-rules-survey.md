# 狼人杀规则调研报告（2026-09）

> 目的：为 Colosseum 平台全新狼人杀引擎的需求 PRD 提供权威规则输入。
> 平台形态：纯 AI 博弈观战——所有座位由 LLM Agent 扮演，另有 AI 主持人（Moderator）；
> 引擎负责阶段推进、行动校验、死亡结算、胜负判定。
> 现状引擎位于 `src/games/werewolf/engine/`（简化版固定 6 人局），本文第 4 节给出逐项差距表。
> 调研日期：2026-09-08。来源以中文圈官方/主流规则为主，辅以国际 Mafia/Werewolf 对应关系与 AI/LLM 研究论文。

---

## 1. 标准规则梳理（中文圈规则为主）

### 1.1 角色全集与定位

先区分两类"牌"：

- **身份牌（底牌）**：游戏开始时随机分发、决定阵营与技能的角色牌，如村民、狼人、预言家等。
- **功能牌/附加牌（警徽）**：警长（ Sheriff ）不是身份牌，而是白天竞选产生的**功能职位**，
  任何存活玩家都可竞选获得，拥有票权加成与归票发言权，死亡时可移交或撕掉警徽。

#### 好人阵营——神职（有夜间技能）

| 角色 | 技能 | 发动时机 | 次数限制 | 关键边界 |
| --- | --- | --- | --- | --- |
| 预言家（Seer） | 每晚查验一名玩家，得知其「好人 / 狼人」 | 夜间，预言家行动阶段 | 每晚 1 次，不限总次数 | 不能验自己；**结果只有二值（好人/狼人）**，不透露具体身份（部分板子对白痴等特殊身份显示特殊，见各板子说明） |
| 女巫（Witch） | 解药救活当晚被刀者；毒药毒杀一名玩家 | 夜间，狼人行动之后（需被告知刀口） | 解药、毒药各 1 瓶，**同一晚最多用一瓶** | ① 不可自救（网易官方：全程不可自救；面杀/部分平台：仅首夜可自救）② 用药当晚不能再救/毒第二人 ③ 毒死无遗言、毒死猎人则猎人不能开枪 ④ 守卫守护挡不住毒药（"毒穿"） |
| 猎人（Hunter） | 出局时开枪带走一名玩家 | 白天宣布死亡后（或夜间死亡次日宣布后） | 整局 1 次 | ① 被狼刀、被投票放逐可开枪 ② **被女巫毒死不能开枪**（部分规则：被殉情、被梦游出局也不能）③ **被奶穿（同守同救）可开枪**（视同被狼刀，网易官方规则）④ 可以不开枪（憋枪）⑤ 猎人与狼王互射时双方技能均可发动 |
| 守卫（Guard） | 每晚守护一名玩家免受狼刀 | 夜间，通常最先行动 | 每晚 1 次，不限总次数 | ① **不能连续两晚守护同一人** ② 守护只防狼刀，**防不了毒药** ③ 与解药同救一人=「同守同救/奶穿」，该玩家仍然死亡 ④ 可以守自己（受连守限制约束） |
| 白痴（Idiot） | 被投票放逐时翻牌免死 | 白天放逐结算时 | 整局 1 次 | ① 翻牌后继续存活、可继续发言，但**失去投票权** ② 狼人仍需在夜里再刀他一次才能使其出局 ③ 被 夜间刀死/毒死 等非投票方式出局时技能无效，直接死亡 ④ 部分规则翻牌后不可再获警徽/移交警徽 |
| 长老（Elder，村长） | 第一次受到狼刀不死（需两刀） | 夜间结算时被动 | 整局 1 次免狼刀 | ① 被女巫毒死/被投票放逐则一次即死（且部分规则：女巫毒死长老时解药同时失效）② 若被好人阵营投出/毒出，部分规则有惩罚条款（神职失去技能），各版本差异大，竞技局少用 |
| 摄梦人（Dream Weaver） | 每夜标记一名"梦游者"，梦游者当晚免疫一切死亡但次日与摄梦人共命运 | 夜间 | 每晚 1 次 | 网易板子角色：摄梦人死亡则当晚梦游者一同出局；与女巫/守卫结算交互复杂，竞技规则明确列出计分修正 |
| 丘比特（Cupid） | 首夜将两名玩家连为情侣（可以连自己） | 首夜，通常最先行动 | 整局 1 次 | ① 一方死亡另一方立即殉情出局 ② **若情侣为一人狼一人好人，则形成第三方阵营**：需杀光其余所有玩家（情侣二人最后存活）才获胜 ③ 殉情死亡视为夜间死亡（猎人殉情不能开枪） |
| 盗贼（Thief） | 首夜先于所有角色行动，从两张多余身份牌中选一张替换自己的底牌 | 首夜最先 | 整局 1 次 | 两张多余牌中若有狼人则**必须**选狼人；丘比特局首夜顺序：盗贼 → 丘比特 → 守卫 → 狼人 → 女巫 → 预言家 |
| 骑士（Knight） | 白天发言阶段可翻牌与一名玩家决斗，若对方是狼则狼出局，若是好人则骑士自尽 | 白天 | 整局 1 次 | 决斗后直接进入黑夜（跳过后续发言/投票）；用于白狼王骑士板子 |

| 角色 | 说明 |
| --- | --- |

#### 狼人阵营

| 角色 | 技能 | 边界 |
| --- | --- | --- |
| 狼人（Werewolf） | 每晚与同伴共同选择一名玩家刀杀；**可自刀、可空刀** | ① 狼人夜间互相认识 ② 白天可**自爆**（翻身份牌，直接吞掉发言权进入黑夜，非最后一狼时可爆）③ 狼队无法统一意见时视为空刀 ④ 首夜狼人即知晓队友 |

### 1.2 夜晚行动顺序与结算顺序

**行动顺序（法官唤醒顺序）各版本存在差异，但结算模型是一致的：**

| 版本 | 夜间顺序 |
| --- | --- |
| 面杀经典（alwa.info / 传统桌游） | 盗贼 → 丘比特 → **守卫 → 狼人 → 女巫 → 预言家** → 猎人（仅确认能否开枪） |
| langrensha.net 常见口径 | **守卫 → 狼人 → 女巫/预言家 → 猎人 → 白痴**（预言家顺序灵活，"几乎可以在任何顺序睁眼"） |
| 网易官方 APP | 狼人（45s 商量）→ 预言家 → 女巫（被告知刀口）→ …（APP 内部封装，玩家无感知顺序） |
| 竞技面杀完整板 | 丘比特 → 盗贼 → 守卫 → 狼人 → 狼美人 → 女巫 → 预言家 → 猎人 → 白痴（白痴仅首夜确认身份） |

**对引擎的关键结论**：行动顺序只影响"女巫是否已知刀口"等信息可见性时序，**不影响结算结果**——所有夜间动作先收集、后统一结算。引擎应采用「收集动作 → 统一结算」模型而非「边行动边结算」。

**夜间死亡结算规则（逐条）：**

1. **狼刀**：狼人共同选择的击杀目标。空刀（无人死）/ 自刀（刀队友或自己，骗药）均合法。
2. **守护**：守卫守护的目标当夜免疫狼刀；不能连续两晚守同一人。
3. **解药**：只能救"当晚被狼刀的目标"（不能救被毒者、不能救已被毒的同晚目标）。
4. **同守同救（奶穿）**：守卫与女巫同时作用于同一被刀目标 → **该目标仍然死亡**。经典口诀"盾药不相溶"。
5. **同守同毒（毒穿）**：守卫守护挡不住毒药 → 被毒者死。
6. **毒药**：目标死亡，无遗言；猎人/狼王被毒不能开枪；摄梦等特殊板子另有交互。
7. **同晚双死**：被刀者与被毒者可为两人（甚至理论更多），白天公告"双死"（不公布死因，暗牌局也不翻牌）。
8. **狼刀在先原则**：白天结算时若狼人屠边与好人团灭最后一狼同时达成（如狼刀屠民的同时女巫毒死最后一狼），判**狼人获胜**。
9. **猎人夜间死**：次日白天宣布死亡后才可开枪；枪杀目标死亡时间视为与猎人同一时间（猎人白天死则目标视为白天死，有遗言；夜晚死则目标视为夜晚死）。
10. **平安夜**：无人死亡（空刀 / 被救 / 被守），主持人公告"昨晚是平安夜"。

### 1.3 白天流程

#### 警长竞选（仅首日，12 人标准局必设，9 人局可选）

标准流程（12 人局口径）：

1. **上警阶段**：法官宣布上警，玩家选择是否上警（警上）。上警者有竞选资格；**上警者无论是否退选都没有选警长的投票权**。
2. **竞选演讲**：警上玩家按顺序发言。
3. **退水（退选）**：演讲完毕后可宣布退出竞选；**退水后丧失投票权**。
4. **警下投票**：未上警的玩家（警下）投票，得票最多者当选警长。
5. **平票处理**：平票 → PK 发言（后发言者先发言）→ 再投票 → **再次平票则本局无警长**。
6. **吞警徽**：竞选发言阶段有狼人自爆 → 本局没有警徽（部分规则：双爆吞警徽，即两名狼先后自爆同样吞徽）。

警长权力：

- 白天发言**总是最后一个**（归票发言权）；有警长时由警长决定发言方向/顺序。
- 投票时 **1 票计 1.5 票**（网易官方）或 2 票（部分面杀规则）。
- 死亡时可**移交警徽**给任意存活玩家，或**撕掉警徽**（本局 thereafter 无警长）。
- **警徽流**：警长（通常为真预言家）事先宣告未来警徽流向（"先验 3 号后验 8 号"），死亡时通过移交/撕徽传递验人信息——这是预言家玩法核心，引擎须支持"警徽移交目标"这一动作。

#### 无警局流程

- 发言顺序由法官决定，通常**从死者下一位开始**（SNRS，"从死左/死右开始"），或按座位顺时针。
- 无警徽加成票。

#### 常规白天（每个白天）

1. **宣布夜死**：主持人宣布昨晚死者（"X 号、Y 号出局"）或平安夜；**不公布死因、不翻身份牌**（暗牌局）。
2. **遗言**：见下。
3. **发言**：所有存活玩家按顺序发言（12 人局常规每人 60–120s，警长 90–150s）。
4. **放逐投票**：所有人同时投票（可弃票），得票最多者出局。
5. **出局遗言** → 进入黑夜。

#### 发言顺序规则

- 有警长：警长决定从谁开始、往哪个方向（从警长左/右或从死者下一位）。
- 无警长：法官定，惯例是**从死者下一位玩家开始**（首日无死者时从某个固定规则开始，如警长竞选后 1 号位或随机）。
- **AI 引擎需要显式的 speechOrderPolicy 配置**（seat-from-first / from-dead-next / sheriff-decides）。

#### 遗言规则（各死亡方式差异）

| 死亡方式 | 遗言 | 备注 |
| --- | --- | --- |
| 首夜被刀 | **有遗言** | 网杀通用：首夜死者有遗言；若首夜死者无遗言 → 推断是被毒死 |
| 首夜之后的夜晚被刀 | 无遗言 | "晚上死亡的玩家，只有首夜有遗言"（网易官方） |
| 被毒（任何夜） | **无遗言** | 好人靠"无遗言"反推毒杀 |
| 白天被投票放逐 | **有遗言** | 每个白天出局者均有遗言（网易：60–120s） |
| 被猎人/狼王开枪带走 | 白天枪杀有遗言；夜间枪杀（视为夜晚死）无遗言 | 枪杀目标死亡时间与开枪者同步 |
| 自爆的狼 | 有 30s 遗言（网易规则） | 面杀部分规则自爆无遗言 |
| 殉情（丘比特） | 视同夜间死亡 | 无遗言（首夜除外） |

### 1.4 投票规则

- **相对多数（plurality）**：得票最多者出局，**无过半数要求**（网易官方放逐与警长竞选均为相对多数）。
- **平票处理（放逐）**：平票 → 平票者 PK 发言 → 全场再投（只能投 PK 者）→ **再次平票则本轮无人出局**，直接进入黑夜（"平安日"）。
- **平票处理（警长竞选）**：平票 → PK → 再平票 → 本局无警长。
- **弃票**：合法（计 0 票）。警上退水者、白痴翻牌者无投票权。
- **票权加成**：警长 1.5 票（网易）/ 2 票（部分规则）。

### 1.5 胜利条件

| 模式 | 狼人胜利 | 好人胜利 |
| --- | --- | --- |
| **屠边局**（9/12 人标准） | 杀光**所有神职** 或 杀光**所有平民**（任一边） | 放逐/消灭所有狼人 |
| **屠城局**（6 人等新手局） | 杀光**所有好人** | 消灭所有狼人 |
| 第三方（丘比特链） | —— | 情侣为狼+好人混搭时，两人需成为最后存活者 |

补充：

- **狼刀在先**：同一次结算中狼人达成屠边与好人达成屠狼同时成立时，判狼人胜。
- **票权/人数 parity**：线上常见附加规则"存活狼人数 ≥ 存活好人数即狼胜"（屠城局的等价快速判定），网易 6 人局采用"杀光所有好人"口径。
- 引擎需把 winConditionPolicy 做成配置：`kill-side`（屠边）/ `kill-all`（屠城）+ 狼优先原则开关。

### 1.7 边界与裁决汇总（引擎必须逐条实现或显式配置）

1. **连狼自刀**：合法（狼刀自己骗女巫解药）。
2. **空刀**：多数规则合法（狼队故意空刀做平安夜）；狼队意见不统一 → 强制空刀。少数面杀约定不允许空刀。
3. **女巫首夜自救**：网易官方"全程不可自救"；大量面杀/其他平台"首夜可自救、之后不可"。**必须做成配置项**。
4. **守卫连守**：不能连续两晚守同一人（含守自己）。
5. **同守同救 = 死**（奶穿）；**守护不挡毒**（毒穿）。
6. **猎人被毒不能开枪、被奶穿可开枪、被投/被刀可开枪**；可憋枪。
7. **平安夜公告**：无人死亡必须显式公告"昨晚是平安夜"（这是重要公共信息）。
8. **双死公告**：公布死亡人数与座位，**不公布死因、不翻牌**（暗牌局口径）。
9. **死因隐藏**：玩家只能通过遗言有无、翻牌与否间接推断刀/毒。
10. **狼刀在先**：同时达成双方胜利条件时狼人胜。
11. **白痴翻牌**：被投出局翻牌免死但失去投票权，此后被刀/被毒正常死亡。
12. **自爆**：白天发言阶段狼可自爆，直接进入黑夜；自爆狼王不能开枪；竞选阶段自爆吞警徽。
13. **警徽**：1.5/2 票、最后发言、死亡移交或撕毁；退水/警上者无选举权。

## 3. AI/LLM 狼人杀研究与实践

### 3.1 论文机制要点

**arXiv:2309.04658 — Exploring Large Language Models for Communication Games: An Empirical Study on Werewolf（ tuning-free LLM 狼人杀）**
[abs](https://arxiv.org/abs/2309.04658) · [html](https://arxiv.org/html/2309.04658v2) · [代码](https://github.com/xuyuzhuang11/Werewolf)

- **配置**：7 人局——2 狼 + 2 民 + 1 女巫 + 1 守卫 + 1 预言家（gpt-3.5-turbo，ChatArena 后端）。
- **记忆三视角**：
  - 新鲜度 O：最近 K=15 条消息直接进 prompt；
  - 信息量 V：按规则打分（角色宣布=5、出局=4、身份推测=3、用药=2、其他=1），取 top-N；
  - 完整性 R（reflection）：从角色专属问题池选 L=5 个 + 自由生成 M=2 个问题，用微调 SentenceBERT 检索 top-T 消息逐条回答，再对 O/V/答案做总反思。
- **经验（Experience）**：局末把 (reflection, response, score) 存入经验池；分数 = 赢家 1000−T_max、输家 T_max（奖励速胜/慢败）。跨局检索：embedding 余弦相似度 ≥0.85 截 50 条，用"最差经验 + 中位经验"生成模仿好、规避坏的建议。**经验池只给好人阵营**（狼为固定基线）。
- **信念（Belief）**：论文**没有显式 belief 模块**，最接近的是 reflection R（局面总结）与离线分析用的 Trust Relationship Table——新引擎的 belief 状态属于自选增强项，不是复现必需。
- **信息可见性**：每人只知自己身份；夜间狼人互见队友与刀票、女巫被告知刀口、预言家私收验人结果、守卫私选守护目标；白天全员公开轮流发言 + 投票，主持人**公开宣布死讯/平安夜**。
- **对新引擎的要求**：引擎事件流必须能按 audience 重放——每个 agent 的 prompt 只能由"它可见的事件"构建（第 3.3 节矩阵）。

**arXiv:2402.02330 — Enhance Reasoning for LLMs in the Game of Werewolf（9 人局双系统推理）**
[abs](https://arxiv.org/abs/2402.02330)：LLM 与外部 Thinker 模块通信，Think-Act 双系统（快系统 ReAct 式行动、慢系统深度推理），9 人局。说明：引擎应把"行动请求"与"推理上下文"解耦，允许 agent 侧挂接慢思考。

**arXiv:2404.01602 — Exploring LLM-based Agents for Werewolf with Sheriff Setting（含警长设定的 LLM 狼人杀）**
[pdf](https://arxiv.org/pdf/2404.01602)：直接研究**警长竞选**对 LLM agent 博弈的影响——对 Colosseum 要不要实现警长系统最有直接参考价值。

**arXiv:2310.18940 — Language Agents with Reinforcement Learning for Strategic Play in the Werewolf Game**
[abs](https://arxiv.org/abs/2310.18940)：RL 微调 agent（LLM 生成候选+价值网络），证明 LLM agent 存在可被训练修正的策略偏差。Colosseum 的 Profile 系统若未来支持强化，引擎需输出可训练的结构化轨迹。

### 3.3 信息可见性工程化：audience 标记 + 隔离矩阵

**引擎红线**：每个 GameEvent 必须带 `audience` 字段（`public` / `wolves` / `self:<agentId>` / `sheriff` / `moderator-only`），agent prompt 一律由"该 agent 可见的事件子集 + 公共事件"重放构建，**绝不把全局 state 直接丢给模型**。

夜间知识隔离矩阵（12 人预女猎守板为例；✓=可见，✗=不可见）：

| 事件 | 狼(全体) | 预言家 | 女巫 | 守卫 | 猎人 | 平民 | 主持人 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 狼队身份与刀口目标 | ✓ | ✗ | ✗ | ✗ | ✗ | ✗ | ✓ |
| 守卫守护目标 | ✗ | ✗ | ✗ | ✓ | ✗ | ✗ | ✓ |
| 刀口是谁（用于决定救药） | ✓ | ✗ | ✓ | ✗ | ✗ | ✗ | ✓ |
| 女巫用药与否/目标 | ✗ | ✗ | ✓ | ✗ | ✗ | ✗ | ✓ |
| 预言家验人结果 | ✗ | ✓ | ✗ | ✗ | ✗ | ✗ | ✓ |
| 猎人能否开枪（毒死禁枪） | ✗ | ✗ | ✗ | ✗ | ✓ | ✗ | ✓ |
| 白天死讯（人数/座位） | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 死因（刀/毒/枪） | ✗ | ✗ | ✗ | ✗ | ✗ | ✗ | ✓ |
| 死者身份牌（暗牌局） | ✗ | ✗ | ✗ | ✗ | ✗ | ✗ | ✓ |
| 所有公开发言/投票/遗言 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

对引擎的落地要求：

1. 事件是唯一事实源（event-sourcing），可见性过滤在事件层而非 state 序列化层。
2. "女巫被告知刀口"必须是独立的 `night/knife-target-reveal`（audience=女巫）事件——这是标准规则的女巫决策前提。
3. "猎人能否开枪"需要主持人私发 `day/hunter-can-shoot`（因为死因对猎人也不公开，主持人代为裁决）。
4. 主持人（GM）可见一切，但主持人的**播报**事件要区分"公开播报"（死讯、平安夜）与"私下确认"（猎人开枪许可）。
5. 观战端（spectator）可以看全量（上帝视角），但回放单 agent 视角时用同一套 audience 过滤——这直接复用为"思考链日志"的产品能力。

## 5. 对新引擎 PRD 的输入清单

### 5.1 v1 规则范围建议

**建议：直接做「配置驱动引擎」，以 6 人板为首发预设、12 人预女猎白为展示目标板。**

理由：

1. 平台卖点是观赛 + Profile 博弈，板子是"赛事格式"，必然多元；把角色/阶段做成数据（RoleDefinition + PhaseGraph + RuleConfig）的成本，低于在硬编码引擎上二次开洞（现状 22 项差距中过半源于硬编码）。
2. 学术实现（2309.04658 用 7 人守卫板、2402.02330 用 9 人板、2404.01602 用带警长板）证明 agent 侧与板子解耦完全可行——agent 只依赖事件流与合法动作集，不依赖具体板子。
3. 分期建议：
   - **v1（M1）**：配置驱动核心 + 6 人板（现板子）+ 9 人 333 板（预女猎，屠边，无警长）；补齐：死亡公告事件、死因隐藏、遗言、平票 PK、女巫刀口告知、屠边判定。
   - **v1（M2）**：12 人预女猎白/预女猎守 + 警长全流程（上警/退水/PK/警徽流/移交/吞徽）+ 守卫（奶穿/毒穿/连守）+ 猎人（禁枪裁决）+ 白痴。
   - **v2**：自爆、空刀合议、丘比特/盗贼第三方、狼王/白狼王、明牌局、扩展角色。
4. 事件层一步到位按 audience 设计（第 3.3 节矩阵），避免"先 public 后补权限"的重放不可复现问题。

### 5.2 开放决策点（需产品拍板）

| # | 决策点 | 选项与建议 |
| --- | --- | --- |
| 1 | **板子官方口径** | 以网易官方为准（女巫全程不可自救、1.5 票、暗牌）还是以面杀竞赛为准（首夜可自救）？建议：默认网易口径 + 全参数可配，赛事可自定义 |
| 2 | **是否上警长系统** | 12 人局建议上（竞技核心+观赏性）；9 人局可选；6 人局不上。参考 arXiv:2404.01602 |
| 3 | **遗言策略** | 建议 `first-night-and-day`（网易口径）；被毒无遗言作为推理线索保留 |
| 4 | **女巫自救** | 建议 `first-night-only`（面杀主流、对 6 人板更友好），网易口径作为赛事配置 |
| 5 | **死因是否公开** | 建议不公开（标准暗牌）；观赛端上帝视角全量可见 |
| 6 | **发言顺序** | 建议 `from-dead-next`（更有博弈感），提供 seat/sheriff-decides 配置 |
| 7 | **平票策略** | 建议 PK 发言+再投+再平无人出局（标准）；AI 局需评估 PK 轮的 token 成本 |
| 8 | **狼刀合议机制** | 最后一狼独立决定 / 多数票 / 队长制？AI 层建议"讨论后由存活狼多数决，平票=空刀" |
| 9 | **发言长度/轮次预算** | 现 200 字硬上限是否放宽为按板子配置（12 人局更长发言）？关系到 token 预算 |
| 10 | **是否支持第三方阵营**（丘比特链） | v2 再议，牵动胜利判定复杂度 |
